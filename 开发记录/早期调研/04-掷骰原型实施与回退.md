## 范围与验收

本轮沿用上一份方案的三项验证范围：完整常见骰组与正确点数、3D 投掷呈现、动画中断后保留同一判定结果。判定、浏览器本地记录、动画适配层和界面各自独立。

判定模块先使用运行环境内置的安全随机源与无偏整数映射，不依赖动画库。百分骰按十位骰与个位骰拆分。动画只能呈现已经生成的点数，不能悄悄重掷。

先验证一套深色骰盘样式。皮肤商城、完整 D&D 战斗规则、AI 服务、账号及云存档不在本轮范围。

## 怎样安全回退

回退前先查看工作区，保存尚未提交的改动。已提交步骤可以在新的分支查看旧保存点，也可以使用 `git revert` 创建反向提交，保留原历史。不要用强制清理或重置去覆盖未知改动。

浏览器本地判定记录与 Git 分开保存。回退源码不会删除浏览器记录。记录带版本号；不兼容或损坏时应明确提示，不静默当成成功恢复。

离线 HTML 属于可重建产物，不纳入 Git。回退到支持离线构建的提交后，执行 `npm run build:offline` 再打开 HTML，保证交付文件与源码一致。回退到 `e5f2fef` 或更早版本时使用旧开发服务入口；磁盘上已有的离线 HTML 不会随切换源码自动变化。

## 扩展路径

动画层只接收判定记录并报告完成或失败。后续可以更换动画库、修改配色、加入新界面，不必修改随机源和正式点数。当前支持同种与不同种骰子组合、整体加一个 1～20 的数值；自由文本公式、优势劣势和更复杂修正仍可在规则层单独扩展。

## 打不开问题的修复

2026-10-22 实际复现：4173 端口没有服务监听，访问返回 `ECONNREFUSED`。旧地址依赖临时服务进程，没有服务时无法打开；交付时不能把该地址作为持久入口。

采用同一套源码与锁定引擎生成单个 [命运骰盘.html](掷骰原型/命运骰盘.html)，启动脚本改为直接打开它。没有新增依赖、桌面软件框架或后台常驻服务，画面配置保持一致。原开发服务保留，适配层仍然支持原有模块入口。

已把单个 HTML 复制到独立测试目录，在 Edge 断网模式下完成全骰型、较多骰子、跳过重播、刷新恢复和保存失败检查，渲染调用间隔与原版处于相近范围。实际启动脚本在不含 Node 的子进程环境中返回 0 且无错误。

目前更换为离线文件的代价是浏览器存储范围变化，旧网址的上一掷不会自动迁移。未验证其他浏览器或跨电脑使用；没有因此扩展记录迁移、导出等功能。

## 混合骰池与附加数值

用户于 2026-10-22 明确要求同种及不同种骰子多选并求和，以及在骰子和上加 1～20，两项能够同时使用。本轮只实现这两项能力，没有加入取高、取低或自由公式解析。

请求由各骰型数量和一个整体附加值组成，合计最多 20 颗逻辑骰。新记录格式为 v2，单独保存每组点数、骰子和、附加值和最终值，动画只处理物理骰子，不再计算附加值。这样可以避免每颗骰子重复加值，或重播时再次累加。

新版读取 v2 键优先，没有 v2 时读取原 v1。新投掷写入独立的 v2 键，保留原 v1，回退代码时不会丢掉旧版可读记录。旧版无法显示新混合结果，但其 v2 数据仍保存在浏览器中。源码回退后需重新生成离线 HTML，才会切换实际页面版本。

实际检查：17 项自动检查通过；断网 Edge 完成全骰型和原恢复流程回归，并通过 `2d6 + 1d20 + 5`、`1d4 + 1d10 + 2d100 + 20` 的真实动画及最终合计检查。重播、刷新保留加值，旧版记录实际恢复与后续保留均已核对。
