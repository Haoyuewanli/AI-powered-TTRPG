# 地图窗口开发范围与验收

更新：2026-11-01。状态：用户已确认四批一起连续完成，开发期间暂时离开。以下范围、演示边界及实施顺序已获本次授权。第6项为空，暂不补写。功能与实际检查结果以交付记录为准。

## 目标与交付

本对话开发地图窗口，以《风骸岛之龙》为测试模组，所有可操作演示采用HTML。完成后再回主对话整合。沿用已有本机Node.js、浏览器JavaScript与CSS，不新增依赖。

在`开发记录/平台设计/地图窗口预览/`实现独立预览，确认体验后再整合正式平台。预览读取本机指定的模组原文和图片，布局、标记和编辑状态另存演示文件。临时截图、检查输出和派生内容放`开发记录/临时/`，第三方全文及私人存档不提交。

## 用户已确认的行为

| 能力 | 本次要求及验收方式 |
| --- | --- |
| 唯一地图目录 | 右侧只列地图层级，例如风骸岛→海藻洞穴→B1入口隧道。同一地点不因主持人图、玩家图、标注或故事条目而重复列出；核对稳定地点身份后合并图片版本，不能仅按同名合并。 |
| 同模组共用画布 | 同模组图片地图与文本地图同时放在一个可平移、缩放的画布上，父子地图用细线向四周展开连接。图片保留原色，自带可改色边框。无独立图片的末级区域以区域名文本框表示，并连接上级。核对全貌、局部以及拖动后连线位置。 |
| 基础绘制工具 | 可以添加简单几何形状、仅有边框的形状、文本框及箭头，并编辑对象颜色；可修改画布背景、方格或点阵的大小与颜色。核对新增、选中、手动布置及缩放后的坐标。 |
| 箭头吸附 | 地图与文本框有四角及四边中点，共八个吸附点。箭头起点和终点均可吸附；目标移动后连接应保持。核对八点、两端及不同缩放倍率。目录细线和用户箭头职责分开，避免修改箭头破坏目录关系。 |
| 玩家标记 | 由主持人手动放置，名字显示在标记上方，默认Player；放置后可选颜色、自定义名字和重命名，同名标记允许重复。标记使用独立ID，核对同名两枚各自移动、改名及保存恢复。 |
| 地图旁的信息框 | 图片地图旁有共享情况、模组描述、移步换景三框；文本地图旁只有后两框。信息框附属对应地图，避免混入右侧目录。核对地图移动后附属框仍可找到且不会串内容。 |
| 模组描述与移步换景 | 模组描述严格依据原文基础描述，并可定位来源。移步换景结合全模组的人物与剧情，整理进入地点时有依据的感官、可能遇到的人和可能发现的事；不硬凑缺乏依据的感官，不把可能事项当成已经发生。两种内容明确分开。 |
| 共享图片 | 图片地图的下拉框可勾选接收玩家。玩家仅收到选定图片，其他内容均不接收，包括画布对象、玩家标记、文本地图、地点说明、提词、目录、共享名单及主持内容。此项按本次要求更新，替代旧问卷中可共享角色坐标点的默认边界。 |
| 原图标注跳转 | 对原图上的×、地点编号等逐项核对位置与目标，覆盖可交互按钮。点击后画布聚焦到对应图片或文本地图，目录同步定位；浏览不改变玩家标记位置。核对缩放、平移后热点仍与原标注重合。 |

## 已确认实施顺序

用户已一次确认整份范围，连续推进，不逐按钮请求许可。

1. 目录、地图图片身份与画布布局：核对图像，建立唯一地图树，同屏铺开图片及文本地图，完成目录及原图热点聚焦。
2. 编辑：补绘制、对象拖动、颜色、背景和网格控制，完成箭头两端八点吸附及玩家标记。
3. 内容与共享演示：逐地点核对基础描述与移步换景，完成附属信息框和按接收人查看的纯图片预览。
4. 恢复与交接：保存并重新载入演示文件，核对窄窗、不同缩放、热点和吸附；整理实际检查结果及主对话整合边界。

## 已确认演示与正式整合边界

- 演示中的玩家列表使用虚构测试名字；共享勾选和接收结果可在本机验收。实际玩家身份、第二设备传送和正式授权接口回主对话整合时接入，不将本机预览标成真实联机成功。
- 玩家接收预览应只获得允许的图片数据，不能先载入主持人完整数据再隐藏。图片版本未核对时明确提示，不自动选择候选图发送。
- 演示布局以本地文件保存和恢复，浏览器缓存只能作临时草稿，不替代正式文件。保存格式不擅自改变主项目尚未对齐的MD与JSON边界。
- 地点目录、图片版本、对象布局、内容来源与共享清单各有清晰职责。后续更换模组通过资料适配接入，不把风骸岛地点写死在通用交互代码。
- 正式整合继续使用既有团上下文、状态版本冲突保护与本机权限边界；不整份覆盖正式地图模块，不改变原战斗核心。
- 几何工具先覆盖矩形、椭圆及其空心边框，文本和箭头可选中编辑。对象调整尺寸、删除与撤销的具体手势在HTML演示中给出，不引入额外图形库。
