# 地图窗口整合说明

本轮以独立HTML完成地图交互开发，正式入口、团存储和真实玩家联机尚未接线。回主对话时按职责接入，不用本目录整份覆盖正式`map-workspace.mjs`。

## 文件职责

| 文件 | 职责与后续接法 |
| --- | --- |
| `index.html`、`style.css` | 演示外框、工具栏、画布与两侧面板。整合时使用原平台容器、外观变量和导航，不另建主窗口体系。 |
| `app.mjs` | 画布坐标变换、绘制、选择拖动、缩放、目录聚焦、热点、属性编辑、历史、文件载入与本机共享预览。正式接入时改用平台提供的上下文和适配接口。 |
| `model.mjs` | 无DOM的布局、八点锚点、端点解析、边界计算及存档校验。可单独复用，不依赖风骸岛的具体地点名称。 |
| `model.test.mjs` | 合成目录与存档的模型检查，不读私人团。 |
| `serve.mjs`及资料适配文件 | 本机限定资料读取与纯图片接收预览。风骸岛资料适配应继续与通用画布交互分开。正式共享由原平台服务端权限层接管。 |

## 资料与布局分开

模组资料提供地图身份、目录关系、图片版本、描述与来源。编辑文件只保存布局和自建对象，不能通过载入文件改写模组原文、图片地址或目录归属。

演示提供给画布的模组数据约定：

```js
{
  id: 'module-id',
  players: [{ id: 'test-player-id', name: '测试玩家' }],
  nodes: [{
    id: 'place-id', parentId: null,
    name: '地点名称', kind: 'image', // 或 text
    width: 1700, height: 1200,
    imageUrl: '/asset/map-id',
    variants: [{ id: 'variant-id', label: '图片版本', url: '/asset/map-id' }],
    description: '依据原文的基础描述',
    sensory: '结合人物和剧情整理的主持提词',
    source: { start: 1, end: 8, label: '原文来源位置' },
    hotspots: [{ label: 'B1', x: 0.25, y: 0.4, targetId: 'place-b1' }]
  }]
}
```

热点坐标相对图片宽高归一化到0～1，不能混入标题或信息框的尺寸。热点目标指向稳定地点ID。目录父子关系与房间间的通道关系分开，主持人图和玩家图是同一地点的图片版本。

正式模组换版时，需要核对地点与图片身份的变化；不能按同名自动把旧团布局绑定到新图。当前风骸岛适配中的人工核对结果也不代表其他模组可自动完成图像识别。

## 画布文件 schemaVersion 1

```js
{
  schemaVersion: 1,
  moduleId: 'module-id',
  nodes: [{ id: 'place-id', x: 0, y: 0, w: 740, h: 550, borderColor: '#708d99' }],
  objects: [],
  settings: { background: '#edf1f3', grid: 'dots', gridSize: 40, gridColor: '#b9c3c9' },
  camera: { x: 0, y: 0, zoom: 1 },
  shares: { 'place-id': { variantId: 'variant-id', players: ['test-player-id'] } }
}
```

对象类型采用`type`字段：

- `rect`、`ellipse`：`id/x/y/w/h/color/fill/borderWidth`，其中`fill`为六位十六进制颜色或`transparent`。
- `text`：增加`text/fontSize`，文本作为数据渲染。
- `player`：`id/x/y/w/h/color/name`；独立ID与显示名分开，允许同名。
- `arrow`：`id/color/borderWidth/a/b`；端点是自由坐标`{x,y}`，或吸附引用`{nodeId,anchor}`。

锚点依次为`nw/n/ne/e/se/s/sw/w`，表示四角和四边中点。端点位置根据目标对象当前几何信息求值，移动目标无需重写箭头坐标。删除自建吸附目标时，应先把关联端点转换成当前位置，避免留下悬空引用。

地图节点的`w/h`包含32像素标题，原图区域的高度按图片长宽比计算。信息框在右侧另占空间；初始布局及全图视野计算为其预留宽度和高度。

`validateDocument`返回经过清洗的新文档。它核对模组身份、完整且唯一的地图ID、有限数值、对象数量与类型、吸附目标、颜色，以及共享图片版本和测试玩家名单。未知内容字段不会覆盖模组资料。导入失败不得替换现有草稿。

此文件格式是独立演示的布局契约，不预先决定主项目尚未对齐的MD与JSON存储边界。正式接入应通过存储适配转换，保留旧格式的迁移路径。

## 正式团状态待接线

1. 地图和故事始终跟随平台正式选择的团，浏览目录或点击房间不改变玩家位置。
2. 模组资料保持只读，团内画布布局、标记和共享状态按团分别保存。迁移现有团前先识别旧状态，不能自动丢弃笔记、探索记录或旧版本引用。
3. 使用已有`expectedRevision`机制保存。切团或重新读取时取消过期请求；迟到响应不得填回新团。
4. 保存冲突保留当前草稿，并要求重新读取后核对；不能自动覆盖另一个窗口或另一设备的较新状态。
5. 撤销仅改变当前编辑历史。若正式共享已对玩家生效，撤销共享也必须重新走服务端授权更新，不能仅修改主持侧显示。

独立演示当前通过下载、载入本地文件保存，不读写正式团，也未实现上述版本冲突接线。浏览器草稿和撤销栈不作为权威持久状态。

## 共享权限待接线

本次最新要求为玩家仅收到选定图片。图片地图可以按玩家选择接收范围；文本地图、画布对象、玩家标记、目录、地点说明、主持提词和共享名单均不发送。

演示使用分开的本机服务入口核对这一边界。接收页面只能请求获准图片，不能先载入主持侧全部资料再用CSS隐藏。真实整合时还需将测试名单替换为当前团真实身份，并由服务端逐次核验接收者、团、图片版本和授权状态。

正式权限撤销应同步阻止后续读取，清理页面中仍显示的获准内容；已被玩家自行保存的图片无法靠界面撤回。不得将本机地址或本机测试名单当作身份认证或第二设备联机已完成。

## 后续验收

整合后需重新核对正常平台入口、四种显示预设、切团、保存与恢复、冲突留稿、过期响应、图片缺失、旧档兼容和实际玩家权限。真实第二设备及不同网络检查独立记录；本机接收预览不代替这些结果。

本目录的实际模型、服务和浏览器检查结果由本轮交付记录补充。正式平台与战斗核心本轮没有因该预览而自动获得回归通过结论。
