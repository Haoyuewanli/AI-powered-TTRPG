# 风骸岛地图窗口 HTML 演示

本目录是地图窗口的独立开发演示。以本机《风骸岛之龙》资料展示整本模组共用画布，供本对话体验和验收；正式平台与已有团尚未接入此界面。

## 打开

双击本目录的`打开地图演示.cmd`。启动后会打开本机浏览器，并保留服务窗口；使用结束后关闭服务窗口即可。

也可在本目录运行：

```powershell
node serve.mjs --open
```

默认读取当前工作区的`项目/`资料，不需要联网或安装新依赖。页面运行期间需要保持本机服务开启；HTML与存档不内嵌整本模组或原图。

本机需有项目已使用的Node.js。D6塔楼内部图从原图插图区域直接提取，使用Windows自带PowerShell/System.Drawing，只在内存生成，不修改原图。

## 这次演示的四批内容

| 批次 | 体验内容 |
| --- | --- |
| 地图画布 | 右侧唯一地图目录；同模组地图同时铺在画布上；父子地图之间的细线；没有独立图片的地点使用具名文本地图；目录及原图标注点击聚焦。 |
| 编辑工具 | 矩形、椭圆、空心边框、文本、箭头和玩家标记；对象移动与尺寸；对象、边框、背景和网格颜色；方格、点阵和大小；箭头两端八点吸附。 |
| 内容与共享 | 每张地图旁的基础描述和移步换景；图片地图附带按玩家勾选的共享面板；通过独立本机接收预览查看获准图片。 |
| 保存与交接 | 下载本地画布文件，再载入恢复；撤销和重做；后续接入主平台的职责、数据及权限边界见`INTEGRATION.md`。 |

这张画布的对象属于演示草稿，不会自动成为正式团进度。模组基础描述保留原文来源；移步换景是主持提词，可能人物及事件仍要结合当时剧情判断。

## 建议体验顺序

1. 点右侧“海藻洞穴”，再点击原图中的B1等按钮，核对视角能进入对应地点。点击“全貌”返回整本模组的地图布局。
2. 选择矩形或椭圆，在画布上拖出形状；勾选“仅边框”再画一个空心形状。选中对象后，在左侧修改颜色、大小或填充。
3. 添加文本框，在左侧输入文字。选择箭头后先点起点，再点终点；靠近地图或文本框四角、四边中点时会吸附。拖动目标，观察箭头跟随。
4. 选择“玩家标记”，点击放置两枚Player。它们允许同名；选中其中一枚修改名字、颜色或位置，另一枚保持独立。
5. 打开图片地图旁的共享情况，选择图片版本并勾选测试玩家，再点左侧对应玩家的接收预览。预览只包含获准图片，不含地图目录、标记或提词。
6. 点“保存画布”，留下下载文件。重新打开演示后点“载入”，选择该文件，核对布局、编辑对象、名字、颜色、网格和共享选择恢复。

## 操作

| 操作 | 方式 |
| --- | --- |
| 平移 | 选择“漫游”拖动；或按住空格拖动；选择工具下也可拖动空白处。 |
| 缩放 | 滚轮、右上方加减按钮，或键盘`+`、`-`。 |
| 全部地图 | 点“全貌”或按`0`。 |
| 移动地图 | 在选择工具下拖动地图标题、图像或文本地图；旁边的信息框跟随。 |
| 移动绘制对象 | 选择工具下拖动对象。玩家标记由主持人手动布置。 |
| 调整大小 | 选中后拖右下角手柄，或修改左侧宽高。图片地图保持原图比例；颜色编辑仅影响边框。 |
| 修改文本或名字 | 双击文本框或玩家标记，或选中后在左侧编辑。 |
| 箭头 | 两次点击确定两端；选中箭头后拖端点可改为其他吸附点或自由端点。 |
| 退出工具 | 按`Esc`取消未完成的操作并返回选择。 |
| 删除对象 | 选中绘制对象后点“删除对象”或按`Delete`。模组自带地图保留在目录中。 |
| 撤销与重做 | `Ctrl+Z`撤销，`Ctrl+Shift+Z`或`Ctrl+Y`重做。 |
| 保存 | 点“保存画布”或按`Ctrl+S`。 |

附属信息框可展开，内容较长时在框内滚动。原文按钮读取该地点的来源片段，基础描述与主持提词分开显示。

缩到全貌时，详细信息框自动收起显示，地点名称和房间编号保持可读；点击标签进入局部。左侧“阅读地图说明”与地图旁“放大阅读”可以用不随画布缩放的字号阅读。缩小时网格只绘制较粗的参考线，避免密集线条遮住地图关系。

## 画布文件

“保存画布”将JSON文件交给浏览器下载，通常位于浏览器设置的下载目录。下载被浏览器拦截时，需要在浏览器中完成保存。仅留在页面中的草稿不代替本地文件。

文件保存地图布局、绘制对象、玩家名字与颜色、网格、视角及共享选择，不复制原图、整本原文或正式团状态。重新使用时先启动本机演示，再点“载入”选择文件；本机原始资料仍需保留。载入时会验证模组身份、对象ID、尺寸、吸附目标及共享图片版本，失败时保留当前画布。

## 共享范围

接收预览采用独立的本机端口，只提供获准的图片数据。主持侧的完整画布、地点目录、基础描述、移步换景、玩家标记和共享名单不发送到该接收页面。

玩家名单为虚构测试名单。当前两个服务都只监听本机，不能作为第二台设备连接或真实玩家联机已完成的证明。共享选择是当前演示状态的一部分；恢复存档后重新应用到本机预览。正式玩家身份、授权及网络传送留到主对话整合。

## 检查与资料边界

模型检查可在本目录运行：

```powershell
node --test model.test.mjs
```

最终实际检查（2026-11-01）：14项Node检查通过，包括8项模型和6组共享服务；真实资料浏览器11组检查通过，逐个点击60个导航标注，核对编辑、同名标记、双击改名、箭头跟随、文件下载后新页面恢复、坏文件保护、共享及撤回、1920/1280/1024/600四尺寸和大字阅读。无脚本错误或外网请求，原文摘要保持。

可复跑：

```powershell
node --test model.test.mjs server.test.mjs
node check.mjs
```

浏览器检查使用开发机已有Playwright/Edge，可通过`RPG_PLATFORM_PLAYWRIGHT_MODULE`及`RPG_PLATFORM_BROWSER`指定，没有安装新依赖。最终证据在`开发记录/临时/地图窗口预览/check-zNHIyo/`，检查截图、下载样例及其他临时输出也集中在该临时区。真实第二设备、正式平台回归及Windows原生外框专项本轮未运行。

演示按当前核对的地点、图片和热点组织，不将预处理包整体升级为内容审核通过。第三方原文与图片保留在本机，不随演示源码提交；原始资料和已有团只读。

当前显示32个地点，其中6个图片地图、26个文本地图。五张主图各含主持/玩家版本；D6两版从已核对的天文台原图插图提取。热点包括×、房间编号、星标、出入口箭头、高程及甲板标题；比例尺与指北针属于图例。基础描述运行时从指定原文行段读取，原文版本摘要不匹配时停止载入，避免行号错位后显示错误内容。
