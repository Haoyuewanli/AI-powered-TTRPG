# 项目目录重整工具

`重整项目目录.mjs`用于把旧本地资料布局迁入“项目/模组”和“项目/资源”。代码迁移由Git流程先完成；本工具处理剩余本地资料、外观、配置、普通依赖目录和旧布局原件。默认只预览，不移动真实资料。

## 预览与执行

```powershell
node 开发记录/工具/重整项目目录.mjs --project-root <项目绝对目录> --report-dir <本轮临时报告目录>
```

报告逐文件记录源路径、大小和SHA-256，列出目标、改写后摘要、同内容跳过项、目录映射和阻塞原因，不把角色HP、私有正文或完整JSON内容输出到控制台。目标不同、归属不明、活动锁和未完成事务都会阻止执行。旧程序或骰盘尚有应由Git移动的源码时也会阻止执行。

```powershell
node 开发记录/工具/重整项目目录.mjs --apply --manifest <预览清单.json> --backup-root <本轮迁移备份根>
```

执行前按同一参数重新扫描，核对源、目标、摘要和锁状态。预览后有变化则停止，须重新预览。工具不停止任何进程。真实执行应由主任务先确认并关闭其已知旧平台；未知Node或身份不明的锁仍会拒绝迁移。

未登记在权威工作区的旧团默认保留并阻塞。只有已明确决定只归档的团，才可用可重复参数`--archive-only-campaign <团ID>`从正式迁移中排除；原件仍进入旧布局备份，不能被当作当前正式模组。

已核对仍需游玩的独立旧团，用可重复参数`--include-detached-campaign <团ID>`纳入新工作区。例如本轮为`--include-detached-campaign solo-trial --include-detached-campaign resource-trial`。它们保留独立团ID、战斗及原字节，原工作区活动团不变；内嵌旧工作区和旧CMD只在备份保留。每个游玩团及预处理均创建故事、对话、战斗三目录，目录清单参与预览指纹。团内新生成的`打开平台.cmd`使用ASCII与CRLF，仅打开项目主平台，需从模组窗口选择所属团，不承诺自动选团。

## 对应关系

- 旧`程序`中的本地`.runtime`、`.tools`等资料进入`资源/程序`，普通`node_modules`整棵移动。浏览器profile与外观JSON保留。源码须先通过Git迁移。
- 旧`骰盘`的生成HTML和普通依赖目录进入`资源/程序/骰盘`；源码同样由Git迁移。
- 旧`资料`进入`资源/资料`。全文和生成资料仍属本机私人资料，不因迁移变成应提交文件。
- `当前/<模组目录>/当前.json`进入`模组/<模组目录>/故事/当前.json`。
- `战斗/<模组目录>/<战斗ID>/...`进入`模组/<模组目录>/战斗/<战斗ID>/...`。
- 旧群聊依据元数据的`moduleId`或默认同值的群聊`id`查管理索引`moduleFolders`，进入所属模组的`对话/<旧群聊目录>`。没有明确关系就停止，不按显示名称猜归属。
- 兼容权威源`资源/故事/Z/战役存档/工作区.json`中每个团，进入`模组/<目录>/战斗/存档`。优先使用管理索引中`campaign:<id>`对应目录；缺少时使用团资料名称加团ID摘要后缀，避免同名覆盖。权威战斗状态以原字节复制，不改数值、不改格式。
- 新工作区位于`模组/工作区.json`，只调整团路径。旧浏览器缓存、锁和临时运行日志不会混入团的正式存档目标，旧布局备份仍保留原件。
- `资源/故事/G/目录迁移.json`以`version:2`保存两种旧存档根以及每个已登记团的精确映射，供项目入口显式旧路径重定向。
- 旧分类里的PDF与图片只有在预处理故事目录已有相同摘要副本后才归档。未匹配原件保留并阻塞；不会为了清空目录直接删除。

只按已登记映射改写项目相对路径。当前、调用及资源描述JSON中的数字保持原值；群聊只改Markdown链接目的地。管理索引的`documents`键和相应摘要同步更新，资源文件列表的路径与摘要一并核对。

## 备份与恢复

备份根必须位于当前工作区中、项目目录外。默认使用`开发记录/临时/迁移备份`。本次备份包括源清单、迁移结果以及`旧布局原件`。

原位置需要改写的索引和资源描述先复制并核对摘要。整棵旧布局目录随后搬入`旧布局原件`，在完整原件可恢复且逐文件摘要相同后才写新目标。普通依赖树从旧布局原件整棵移动到新位置，不复制第二份依赖；迁移结果单独记录其逆向路径。其他业务原件保留在备份中。

若失败，迁移结果标为`incomplete`并给出备份绝对位置，不标成功。恢复时先确认没有平台在使用这些目录，再按`archiveMoves`逆序将旧布局原件搬回原源路径；普通依赖树先按`dependencyMoves`从新位置搬回备份原路径。原位改写文件可用`旧布局原件`内相同相对路径的原件恢复。恢复前同样须检查现有目标，不能覆盖后来产生的玩家进度。

工具不会自动删除或撤销已产生的新进度，也不会自动解决一份未完成迁移。需要检查不完整迁移报告及现有文件后再继续。

完成后重复预览识别`version:2`标记并返回`already-migrated`，不重新写入战斗状态或覆盖玩家之后的变化。标记存在但旧布局仍残留时会报错，不能把部分迁移当成成功。

完成前再次核对所有目标文件（包括同内容跳过项）及全部依赖文件摘要；任何变化都写入不完整报告，不标为完成。

## 安全与检查

所有读写与移动先核对绝对路径和实际目录归属，不跨shell拼接命令，不跟随文件链接或目录联接。普通目录锁会先查PID是否存在，并只读查询进程映像；已知`svchost.exe`等非Node PID复用不会误判成活动战斗，未知映像继续保护。

合成检查：

```powershell
node --test 开发记录/工具/tests/重整项目目录.test.mjs
```

检查使用本轮临时目录内生成的数据，覆盖源摘要、完整原件归档、战斗字节不变、JSON路径和索引摘要、群聊链接、目标冲突、锁、归属、预览后变化、同内容跳过和安全幂等。当前环境不能创建目录联接时，建立链接的场景会明确跳过；不会改真实资料来代替测试。
