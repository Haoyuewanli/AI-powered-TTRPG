# 开发工具

本目录保存维护和核对工具。它们处理开发资料，不参与游戏规则结算；临时输出统一放在`开发记录/临时/`。

## 清理旧测试输出

`清理旧测试输出.mjs`只检查明确许可的测试分类，以及形如`case-ABC123`、`campaign-ABC123`、`browser-ABC123`的生成叶子目录和旧浏览器测试配置。默认只生成清单，不删除。

```powershell
node 开发记录/工具/清理旧测试输出.mjs --report-dir 开发记录/临时/迭代-20261029/开发记录清理
```

默认扫描本工作树的临时根。可以重复传入`--root <绝对目录>`检查多个已确认的临时根。生成的清单列出候选路径、文件数、逻辑字节数、内容指纹、保留项和跳过原因。

核对清单后执行：

```powershell
node 开发记录/工具/清理旧测试输出.mjs --apply --manifest <已保存的清理清单.json> --report-dir <本轮临时报告目录>
```

执行前再次核对绝对路径、根目录归属、链接和文件指纹；清单后有变化的目录保留。每类保留最新样本、能识别的最新成功和最近失败证据，默认还保留最近60分钟内使用的目录。不知道价值的内容、独立报告、截图、工具、表格和来源不会成为候选。

所有`工作树`、`迭代-*`、备份、规则/资料核对、来源和对照目录都保留。扫描原工作区临时根时，不会进入其中的工作树目录。包含目录链接或文件链接的生成副本整棵保留。程序不跟随链接，不停止任何进程，也不压缩旧测试数据另存一份。

这不是任意文件清理器。新测试类别需先确认生成目录结构，再加入许可分类。不要把用户资料或正式存档放进这些生成测试目录。清理报告的字节数是文件内容总长度，不是磁盘分配空间的测量值。

隔离检查：

```powershell
node --test 开发记录/工具/tests/清理旧测试输出.test.mjs
```

## 规则资料核对

`取得不全书.ps1`与`核对不全书.py`保留已有资料取得和校验流程；具体参数与输出以脚本说明为准。执行涉及联网或下载的功能时，遵守项目现有授权与资料许可范围。
