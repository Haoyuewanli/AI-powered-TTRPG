# 单人跑团产品与结构大纲

版本：0.3；更新：2026-10-26。已确认要求与实现建议分开记录。当前已实现首轮本地战斗原型：身份分流、3D棋盘、基本规则、文件存档和主持交接；完整12级月德规则仍未自动化。

## 已确认要求

- 先支持一个玩家，AI 担任 DM，规则目标为 D&D 2024。
- 《5E 不全书》作中文主参考；完整收录不等于全部启用，须区分年份、扩展、旧版与合作内容。有歧义时核对对应官方原文和勘误。
- 正式进度须能保存到本地文件，并能恢复、备份和迁移；浏览器缓存只能辅助使用。
- 机械性的规则校验与结算由本地程序执行，不依赖 AI。
- NPC 的战斗目标、动作、移动及战术选择属于主持职责，可以由 AI 或人工完成；本地程序校验并结算所选动作。
- 主持者可以替换为本地应用调用模型 API、GPT/Workbuddy 等外部聊天工具或人工，共用同一本地进度。
- 修改可回退，职责分开以便扩展；开发文件和正式代码、成果分开放置，小步保存到 Git。

“单人”指一个玩家，角色数及伙伴安排尚未决定。完整下载资料不代表全部规则已被程序实现。

## 职责边界

| 部分 | 职责 | 边界 |
| --- | --- | --- |
| 主持者 | 读取必要局面，描述世界、扮演 NPC、选择 NPC 动作，提出剧情和操作 | 不伪造骰点，不直接改写正式数值 |
| 主持交接 | 送出必要局面与执行结果，接回操作提议 | 先验证可人工交换的格式，再分别接自动接口 |
| 本地核心 | 校验操作、处理骰点和资源、执行已支持规则并提交状态变化 | 机械结算不调用 AI，未实现或有歧义的裁定明确交给主持者/人工 |
| 本地存储 | 保存角色、NPC、世界事实、秘密、进度与可核对的操作记录 | 不以聊天记录或浏览器缓存代替正式文件 |
| 界面和骰盘 | 接受操作，显示角色状态、规则结果和动画 | 展示同一组正式骰点，动画不另掷一次 |

NPC 的战术不在首版硬编码成通用战术 AI。API、外部聊天工具与人工三种方式都应能接到同一本地核心，具体自动接入能力以后分别核对。

## 首个闭环（首轮已实现）

本地文件载入 → 玩家/主持者提交明确操作 → 本地校验和结算 → 保存进度 → 导出结果 → 主持者继续故事。

首轮按用户确认使用Node.js与现有Three.js，局面和操作用JSON人工交接；具体操作与存档格式见 [战斗使用说明](../项目/战斗/README.md)。操作携带战役ID、操作ID、期望版本；局面投影按权限返回。实际API调用和外部工具自动接入以后分别实现。

已核对无AI机械结算、文件重启恢复、权限化人工交接、重复/过期/跨战役提议拒绝、写入故障保护与损坏恢复。完整叙事试玩、真实角色的资源和攻击核对尚待进行。

## 12 级单人战斗原型（2026-10-25 新请求）

### 用户已提出的要求

- 为指定的 12 级角色建立 `单人-12级开卡-XXXX` 子文件夹，保存角色卡；选取不全书中的怪物，保存数据。
- 输入玩家名字或 ID 后显示玩家应知信息；输入 DM ID 后可查看全部信息并控制系统。
- 主持方式保留 GPT、Workbuddy、API 程序和人工替换的可能。
- 3D 棋盘大格 5 尺、小格 1 尺；滚轮或按键缩放，拖动或按键旋转和平移。
- 暂用长方体表示角色，长宽高可设；面积最大的两面作为前后面。

### 首轮范围与验收（用户已确认，2026-10-26 已实现原型）

本轮目标是能在本机打开、保存、重启继续的一场战斗原型。用户已选择“按此首轮范围实施”，确认下列范围与 Node.js、现有 Three.js 的本地技术方案。已有职责边界继续适用。

| 范围 | 首轮验收 |
| --- | --- |
| 角色与对手资料 | 原图逐文件复制并核对 SHA-256；手写抄录单独保存，未核对项不进入正式结算。怪物保留出处、版本、原页与结构化数据 |
| 玩家与 DM 入口 | 玩家收到自己的状态、已揭示棋子与公开日志；不收到隐藏单位、敌方精确 HP、DM 备注或完整存档。DM 可查看、编辑和揭示数据。玩家名字/ID 用于选择身份，首轮曾使用本机凭据；2026-10-26按用户明确要求取消，改为本机直接选择DM |
| 3D 棋盘 | 对照坐标检查 5 尺粗网格、1 尺细网格；滚轮缩放、左拖旋转、右拖平移；键盘提供同等操作和复位。棋子位置、朝向与长宽高可编辑，较大相对面有前后标记；规则占地与外观尺寸分开 |
| 首批机械结算 | 先攻、回合顺序、基本移动、普通攻击命中/伤害、临时生命抵扣和伤害类型处理，由本地程序计算并记录骰点；NPC 选动作由 DM。复杂法术、荒野形态完整替换、触发反应和充能等未支持部分提供明确的人工裁定入口，不伪称完整 D&D 引擎 |
| 本地持久化 | 操作经权限、参数和进度版本检查后保存；重启恢复同一状态；失败不显示保存成功；保留上次完整存档用于恢复，重复/过期操作拒绝重复结算 |
| 主持交接 | 导出明确标注权限的局面包，导入结构化操作提议并经同一核心校验；人工复制粘贴能走通。接口不绑定某家模型，实际 GPT/Workbuddy 自动控制或 API 调用以后分别接入 |

已采用的技术：沿用已安装的 Node.js 与浏览器 JavaScript，复用现有锁定依赖中的 Three.js 0.143.0；本机服务仅监听 `127.0.0.1`，提供一键启动入口，页面由本地服务获取筛选后的局面，正式状态写入本地文件。新模块不借用骰盘的私人状态，未增加框架或联网服务。若后续确需新依赖，先单独取得授权。

正式代码已放 `项目/战斗/`，本地战役放 `项目/存档/单人-12级开卡-<角色名>/`。战役原件、手写抄录、怪物全文与正式进度均排除出 Git；源码、无私人信息的测试和结构说明纳入 Git。角色图使用旧表格本身不能判定玩法年份，须按具体职业特征和数值核对。怪物选择用于系统试验，不据 CR 单独保证 12 级单人战斗平衡。

本地身份分流保护的是应用返回的数据；同一台电脑中能读取战役文件的使用者仍能查看 DM 数据。角色的视觉长宽高不是规则给定的精确体测值，未有原始数据时使用可编辑的显示占位值，并保持战斗占地单独定义。

后续扩展：新增规则动作接到同一校验与结算入口；新主持适配器只交换局面和操作；棋子可换成模型而不改变规则占地；存档携带格式与规则版本以便迁移。首轮不承诺完整法术库、全自动月德变形或外部工具的自动接入。

### 本地日常入口（2026-10-26 用户补充要求）

用户要求随时在本机打开、断网可读写、程序中断后从文件恢复，允许选择网页或窗口方案。沿用已确认的本地Node.js核心和Three.js，新增工作区根目录的 `打开跑团.cmd`；启动核心并确认就绪后，使用本机已有Edge以独立应用窗口显示界面。没有安装桌面框架，也不依赖云端托管；普通浏览器方式保留作回退。

本轮聚焦本地启动与恢复，不扩大战斗规则范围。验收为：固定入口可直接打开；外部网络请求被阻断时能读写存档；关闭窗口、强制终止核心后重新打开，能读取最近成功保存的状态并继续修改。窗口缓存与正式战斗文件分开，未保存的表单输入不等同于正式进度。窗口层不改变规则、身份筛选或主持交接协议。

已实现数据层次：工作区只记团列表与最后打开位置；每个团有稳定ID、团级资料；每场战斗有独立战斗ID、盘面、参与者快照、进度版本、事件与回退历史。操作同时校验团ID、战斗ID和版本，切换时不共享可变状态。战斗使用角色快照；首版新战斗明确选择复制哪份初始状态，不默默回写或覆盖其他战斗。长期角色成长回写是后续明确动作，不与战斗切换混为一谈。

AI接管分两种：GPT/Workbuddy先用界面引导的主持包与返回提议；真正自动循环的API主持仍需另选服务和确认数据发送范围。本轮不索取密钥、不联网发送游戏内容。

| 3 | 短按选中棋子；拖棋子预览落点，松手提交一次；战前为摆放、战斗中为规则移动；空地拖动控制镜头 | 拖棋子不旋转镜头；取消不改进度；超速、越界、碰撞、无权限或过期版本均拒绝并复位；成功仅产生一次记录且可撤销。保留精确坐标入口；高层棋子保持脚底高度，跨层通行仍由DM裁定 |
| 4 | 面对面联机：DM主动开启玩家入口，生成角色专属邀请，同一Wi-Fi通过浏览器加入 | 至少两个隔离玩家客户端检查数据分流、自己的操作和同步；隐藏单位/DM备注不进入玩家响应。关闭分享、撤销邀请或切换战斗后旧邀请与会话失效；真实第二设备连接单独记录 |

每阶段检查并建立本地Git保存点；私人存档、邀请令牌、下载工具和临时截图不提交。正式进度仍以主机本地文件为准；未提交表单不冒充已保存进度。现有真实角色与战斗不用于破坏性测试。

### 布局与交互

界面沿用现有网页和Three.js，不引入UI框架。宽屏为棋盘加行动栏；窄屏使用同一份表单的抽屉，避免维护两套规则输入。准备、先攻收集、战斗、结束各阶段只突出当前相关操作。DM可查看全部资料与代填；玩家只见自己的待办与公开信息。

拖动超过小距离阈值才进入预览，过程中不写存档。落点按规则网格吸附，提交携带开始拖动时的局面版本，交同一核心校验；期间若收到更新，取消或拒绝旧动作，不能悄悄套用新版本。Esc、失焦、指针取消、切换战斗均清理预览。鼠标功能完整验收；触屏以点选、工具开关、基本拖放和页面可用为首轮边界，不新增复杂多指手势系统。

当前先攻仅能由DM随开始指令一次提交。玩家自行填先攻是规则与状态接口的增量扩展，不算纯样式修改。新增先攻收集须校验角色归属、骰数/范围、重复提交和进度版本，并让修改先攻加值、参与者或骰模式后的旧提交明确失效或重新确认。普通攻击继续由本地程序结算；NPC动作选择和复杂裁定仍属主持职责。

### 联机结构与授权边界

一台主持电脑运行规则核心、持有本地存档，同一时刻分享当前一场战斗。本机免口令DM入口仍仅监听环回地址；另开玩家入口及独立会话，使用绑定团、战斗、角色的随机邀请。不能把现有DM服务直接对外开放，也不能根据连接来自环回地址就允许DM，因为线上连接工具也从本机接入。

复用当前角色投影、操作ID、版本检查、串行保存与撤销。同步先用短轮询，避免增加连接框架。局域网普通HTTP需兼容操作ID生成与手动复制。玩家断开不影响主机存档；主机关闭后停止联机，重开从本地进度继续并重新邀请。

推荐线上首版使用官方cloudflared独立程序，仅主机需要下载；无账号或域名要求，玩家用浏览器。使用时玩家可见的游戏数据及操作会经过Cloudflare转发；不暴露本机DM入口、完整存档、角色原图、规则资料副本或其他本地目录。用户已明确授权下载工具和启用此转发方式。默认不开公网分享，不改路由器、不自动改防火墙、不安装系统服务；Windows或网络限制导致连接失败时显示具体诊断。

[Cloudflare官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)（2026-10-26核验）：Quick Tunnel用于试运行，地址每次变化，进程停止即失效，没有可用时间保证，不支持SSE。它是开团期间的远程加入通道；电脑上的固定启动入口与本地文件依旧长期可用。若以后需要固定线上地址或长期稳定服务，再单独选择账号/域名或其他方案。国内外实际网络能否连通以实测为准。

备选为Tailscale私人网络，但主持和玩家设备都要安装并登录，加入步骤更多，因此首轮不并行实现第二套线上通道。官方参考：[设备分享](https://tailscale.com/docs/features/sharing)、[Funnel](https://tailscale.com/docs/features/tailscale-funnel)。

扩展路径：界面工具与规则动作分开；玩家入口只适配已有校验和投影，未来可替换连接方式。首轮不加入云存档、账号系统、多房间同时运行、语音视频、模型自动主持或新素材库。

使用负担验收：首次进入直接看到当前阶段与下一步；非必要设置折叠；联机入口集中“开启、选择角色、复制邀请”；重复打开不要求重填已经保存的数据；错误说明如何恢复，操作中及完成后显示状态。
