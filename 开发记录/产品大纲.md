# 单人跑团产品与结构大纲

版本：0.2；更新：2026-10-25。已确认要求与实现建议分开记录。当前阶段为资料整理与模块边界设计，尚未实现跑团核心。

## 已确认要求

- 先支持一个玩家，AI 担任 DM，规则目标为 D&D 2024。
- 《5E 不全书》作中文主参考；完整收录不等于全部启用，须区分年份、扩展、旧版与合作内容。有歧义时核对对应官方原文和勘误。
- 正式进度须能保存到本地文件，并能恢复、备份和迁移；浏览器缓存只能辅助使用。
- 机械性的规则校验与结算由本地程序执行，不依赖 AI。
- NPC 的战斗目标、动作、移动及战术选择属于主持职责，可以由 AI 或人工完成；本地程序校验并结算所选动作。
- 主持者可以替换为本地应用调用模型 API、GPT/Workbuddy 等外部聊天工具或人工，共用同一本地进度。
- 修改可回退，职责分开以便扩展；开发文件和正式代码、成果分开放置，小步保存到 Git。

“单人”指一个玩家，角色数及伙伴安排尚未决定。完整下载资料不代表全部规则已被程序实现。

## 职责边界

| 部分 | 职责 | 边界 |
| --- | --- | --- |
| 主持者 | 读取必要局面，描述世界、扮演 NPC、选择 NPC 动作，提出剧情和操作 | 不伪造骰点，不直接改写正式数值 |
| 主持交接 | 送出必要局面与执行结果，接回操作提议 | 先验证可人工交换的格式，再分别接自动接口 |
| 本地核心 | 校验操作、处理骰点和资源、执行已支持规则并提交状态变化 | 机械结算不调用 AI，未实现或有歧义的裁定明确交给主持者/人工 |
| 本地存储 | 保存角色、NPC、世界事实、秘密、进度与可核对的操作记录 | 不以聊天记录或浏览器缓存代替正式文件 |
| 界面和骰盘 | 接受操作，显示角色状态、规则结果和动画 | 展示同一组正式骰点，动画不另掷一次 |

NPC 的战术不在首版硬编码成通用战术 AI。API、外部聊天工具与人工三种方式都应能接到同一本地核心，具体自动接入能力以后分别核对。

## 建议的首个闭环（待对齐，未实现）

本地文件载入 → 玩家/主持者提交明确操作 → 本地校验和结算 → 保存进度 → 导出结果 → 主持者继续故事。

建议先用人工交接验证，再接 API 和外部工具。局面、操作提议和执行结果分开；操作编号、进度版本与规则版本便于防止重复执行和旧回复覆盖新进度。具体字段、文件格式、规则范围、界面形态、语言和框架仍待讨论，不因本大纲定案。

未来验收应包括：无 AI 的机械结算、本地文件保存后重启恢复、替换主持者后继续同一进度、重复或过期操作不重复扣资源、故障时保留旧进度。规则与存档用固定输入核对，叙事质量通过实际试玩另行检查。

## 当前成果与限制

已有独立混合骰盘，支持常见 D&D 骰型及整体加值；只有上一掷浏览器记录，没有战役存档或战斗规则。两份早期模组分别为旧版 D&D 5E 和 CoC 7，不是原生 2024 模组，保留作历史资料。

本轮整理和不全书下载、核对结果见 [整理记录](整理记录.md)。第三方资料副本不改写，版本固定；以后更新应另存并核对，不静默覆盖正在使用的规则版本。原始全文不进入 Git，来源与工具可用于重新取得。

尚未决定：角色与伙伴、测试冒险、首批自动化规则、交接字段、技术栈、模型服务及各外部工具的自动接入方法。本轮不安装新依赖、不接入模型、不发送游戏数据。
