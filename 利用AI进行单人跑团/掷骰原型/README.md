# 独立掷骰原型

可在本机浏览器试玩的独立 3D 骰盘。支持 d4、d6、d8、d10、d12、d20 和成对百分骰，每次 1 至 20 组；提供重播和跳过动画，刷新后能恢复最后一次判定。

## 打开骰盘

电脑已装好本轮依赖。双击本目录的 `启动骰盘.cmd`，会启动本机服务并打开默认浏览器。保持启动窗口打开；关闭窗口或按 Ctrl+C 停止服务。

也可使用 Node.js 20 或更新版本，在此目录运行：

```powershell
npm start
```

然后访问 <http://127.0.0.1:4173>。只监听本机回环地址，运行过程不访问第三方服务，也不需要 AI 密钥。

换一份新检出的目录时，先用 `npm ci --ignore-scripts --cache .npm-cache` 按锁定文件安装，再启动。依赖与测试输出均排除出 Git。不要通过双击 HTML 直接打开，浏览器模块需要本机 HTTP 服务。

## 使用方式

选择骰型和数量，点击“掷出骰子”。正式点数先保存到浏览器，再播放动画。重播保留同一组点数，轨迹可以不同；跳过、窗口缩放或动画失败不会重新生成点数。

百分骰的十位与个位外观分开显示；下方结果已经组合为 1 至 100。两颗骰上的 `00` 与 `0` 组合为 100。单独的 d10 中 `0` 表示 10。

保存失败时按钮变为“重试保存这一掷”，沿用待保存的点数。关闭页面前仍须重试成功；尚未写入的内存记录无法跨页面恢复。

每个浏览器、用户配置与地址有自己的本地记录。原型只保留最后一次判定，新投掷保存成功后替换它；不是完整历史或战役存档。清理浏览器数据会删除该记录。

## 检查

```powershell
npm test
```

11 项自动检查覆盖随机映射、所有 100 种百分骰拆分、记录错误、动画结果不一致及本地服务的路径和方法限制。运行环境若限制回环网络，需要在允许本机连接的环境执行服务检查。

`tests/browser-check.mjs` 另用 Playwright 和已安装的 Edge 检查真实渲染。它不属于新增运行依赖，本轮使用 Codex 已捆绑的测试工具；如需复跑，可用环境变量 `DICE_PLAYWRIGHT_MODULE` 指向已有 Playwright 模块，并先启动服务。结果输出到 `test-output/`。

本轮结果与性能条件见 [测试记录](测试记录.md)。

## 模块边界

- `src/rolls.mjs`：请求校验、安全随机数、正式判定记录和显示用骰子拆分。
- `src/journal.mjs`：通过传入的存储接口保存、恢复并校验最后一次判定。当前界面传入浏览器 localStorage。
- `src/animation-contract.mjs`：将正式记录翻译为动画请求，核对动画回传点数；百分骰归组只影响显示层。
- `src/dice-animation.mjs`：唯一接触三维库的适配层，处理播放、中断、尺寸变化和资源释放。
- `src/app.mjs`：界面状态与用户交互。
- `server.mjs`：无额外依赖的本机静态服务。

后续换动画库只需保留适配层的初始化、播放与停止接口，并继续通过点数核对。换配色在适配层的主题配置和 `style.css` 中进行。增加复合骰式或优势劣势时，先扩展规则与记录版本，不让界面自行计算权威结果。

记录格式当前为版本 1，不提供防篡改或多人公平性保证。

## 依赖与限制

直接依赖 `@3d-dice/dice-box-threejs` 0.0.12，间接依赖 `three` 0.143.0、`cannon-es` 0.20.0，均由锁定文件固定，包内保留各自 MIT 许可。当前样式使用程序生成的骰面，没有另取外部模型或纹理素材。

旧版库有 d4 缓存、尺寸变化的资源管理和高刷新率下的物理步长问题，已在适配层集中处理，没有修改 `node_modules`。升级时须重跑全骰型与中断检查，并重新审视这些兼容处理。首版尚未加入音效、自定义模型或战斗规则。

保存点与安全回退方法见 [实施与回退说明](../04-掷骰原型实施与回退.md)。
