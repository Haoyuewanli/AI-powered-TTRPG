# 电脑掷骰效果方案

调研日期：2026-10-21。状态：方案建议，待确认后再实现。未安装依赖，未在本机运行这些库，未测试实际帧率。

后续进度（2026-10-22）：用户已授权试做推荐方案，已完成 [独立骰盘原型](掷骰原型/README.md) 和 [本机测试](掷骰原型/测试记录.md)。下文保留调研时的候选比较和建议，实际完成状态以上述记录为准。

## 推荐怎么做

优先验证一个可在电脑浏览器运行的 3D 骰盘：骰子从边缘抛入、相互碰撞、滚动停稳，配合阴影和碰撞音效，最后突出可读的点数。覆盖完整的常见 D&D 骰组。

对本项目，建议先验证 **dice-box-threejs 的“指定结果后播放落骰”能力**。它能把正式判定结果表现为物理动画，便于记录、重放和错误恢复。另一套 **Dice Box** 适合比较主题效果和性能；**Dice So Nice!** 可作视觉参照，也是一条直接使用现成桌面跑团平台的路径。

这是基于接口与源码的方案判断，尚未形成最终技术选型。最终是否采用浏览器、是否包装独立窗口，以及规则版本，仍由项目发起人决定。

## 三条路线的取舍

| 路线 | 已核对的能力 | 适合本项目的地方 | 限制与维护成本 |
| --- | --- | --- | --- |
| [dice-box-threejs](https://github.com/3d-dice/dice-box-threejs) | Three.js + Cannon ES；文档支持 `6d6@4,4,4,4,4,4` 这类指定结果；可设阴影、声音、材质与抛掷力度 | 适合做独立骰盘，并与程序保存的判定结果对齐；建议优先做验证 | 公开 package.json 当前写 0.0.12，依赖 Three.js ^0.143.0；依赖较旧，现代浏览器兼容和稳定性需要实测 |
| [Dice Box / Fantastic Dice](https://fantasticdice.games/) | Babylon.js + AmmoJS；官方介绍使用 Worker、WASM 等；有主题、完成事件和结果对象 | 主题入口清楚，适合快速比较多套外观与大量骰子的动画 | 已查公开调用说明未看到与上一行等价的指定结果接口；不能直接承诺“外部掷骰后按该点数落地”。物理产生结果时，还要明确怎样记录随机过程和处理超时 |
| [Foundry VTT + Dice So Nice!](https://foundryvtt.com/packages/dice-so-nice/) | Foundry 插件；物理 3D 骰、材质、音效、特效和自定义骰子能力 | 若目标是尽快在现成平台上体验漂亮掷骰，这是可选路径；也适合作视觉标杆 | 依赖 Foundry 平台，基础软件需要购买；本轮未购买。插件及素材的许可须分别核对，不能假定能直接搬进独立应用 |

Dice Box 官方的性能描述属于项目方说明，并非本机测试。不要根据“支持 Worker”就承诺任意电脑都能达到 60 帧。

技术来源：[threejs 版说明](https://github.com/3d-dice/dice-box-threejs)、[当前 package.json](https://raw.githubusercontent.com/3d-dice/dice-box-threejs/main/package.json)、[Dice Box 调用方法](https://fantasticdice.games/docs/usage/methods)、[结果对象](https://fantasticdice.games/docs/usage/objects)、[完成事件](https://fantasticdice.games/docs/usage/callbacks)。

## 骰子必须覆盖哪些

| 逻辑骰型 | 屏幕上显示 | 需要专门核对的地方 |
| --- | --- | --- |
| d4 | 四面骰 | 顶点或底边读数要明确，最终结果文字与实际模型读法一致 |
| d6 | 六面骰 | 数字面或点数面任选其一，优先保持整套外观一致 |
| d8 | 八面骰 | 停稳后上方面读数正确 |
| d10 | 十面骰，个位面 | 单独作 d10 时，面上的 0 表示 10 |
| d12 | 十二面骰 | 不因数字密集而难读 |
| d20 | 二十面骰 | 6/9 有方向标记；自然 1/20 可加轻量特效，但不改变结果 |
| d100 | 一颗十位骰（00、10…90）加一颗个位骰（0…9） | 组合成 1 至 100；00+0=100，00+7=7，30+0=30。不能把两颗骰都按普通 d10 的 1 至 10 相加 |

这里的常见完整骰组是六种基本多面体，加一颗十位骰，合计七颗实体外观。首轮不需要制作一个真正的一百面球形骰。

已在 [threejs 版骰型源码](https://raw.githubusercontent.com/3d-dice/dice-box-threejs/main/src/const/dice.js) 中核对 d4、d6、d8、d10、d12、d20 和十位 d100 的定义。但库里的 `d100` 标签与游戏里的“百分骰结果”不一定是同一个层次，接入时必须验证配对与换算。

两颗 d20 的优势/劣势，以及 2d6、8d6 等骰池，可以使用同一显示模块；取高、取低、修正值和伤害计算应留在规则模块中。

## 建议的视觉方向

优先做一套“深色骰盘 + 蓝绿色或深蓝骰体 + 浅金数字”的样式提案：固定斜俯视镜头，骰子略带圆角，用柔和阴影交代接触位置，数字始终比纹理更醒目。这个配色是建议，尚未确认。

一次普通掷骰建议在 1.5 至 3 秒内完成主要动作：抛入、碰撞、减速、停稳，再出现结果。允许玩家跳过动画，音效可关闭。自然 20 的闪光控制在短时间内，避免持续光效遮住数字。

透明水晶、强折射、多层粒子可以后续比较；首轮先验证清楚、流畅、点数一致，再决定是否增加这些效果。

## 正式结果怎样与动画保持一致

建议流程：

1. 程序检查骰型、数量和表达式，生成唯一判定编号。
2. 程序的随机组件只生成一次正式点数，用无偏映射得到目标范围内的整数，并保存这次判定。
3. 将每颗骰子的点数交给能指定落点的动画适配层。
4. 动画结束时核对面朝向、点数和规则计算；显示结果并推进游戏。

若动画被跳过、窗口缩放或渲染失败，直接显示已保存的正式结果。重播沿用原点数，不能重新抽样，也不能因画面不好看而改变判定。若保存失败，则提示失败并按同一判定编号恢复，避免重复判定。

这是“程序判定，动画负责呈现”的方案。AI 可以解释结果，不负责编造点数。特效条件也从正式点数读取。

## 下一步验证范围与验收建议

建议下一步只做一个独立骰盘验证页，不接 AI、不读取存档，也不安装付费组件。进入实现前确认此范围，并取得新增依赖授权。

| 验证项 | 建议验收方式 |
| --- | --- |
| 全套骰型与落点一致 | 每种骰型检查最小值、最大值及若干中间值，逐颗比对朝上读数和结果文字；百分骰另查 100、个位数和整十数 |
| 好看且顺手 | 用相同镜头、背景与光照比较一套基础材质和一套候选风格；正常投掷、连掷和跳过时都能看清结果 |
| 流畅与失败恢复 | 在用户实际电脑记录浏览器版本、分辨率及配置；以 1080p、最多 20 颗骰、接近 60 fps 为初始目标；检查连续投掷、缩放、后台恢复和超时后仍保留同一结果 |

性能不足时先降低像素比例、阴影质量和特效；空闲时停止渲染。上述数字是建议目标，需要根据实际电脑测量再确认。

## 扩展路径与维护风险

只在判定与动画之间保留一个小适配层：输入骰型及点数，输出完成或失败。这样可以换皮肤、换动画库，或增加独立窗口，而不改写正式判定记录。

首轮最值得查清的是三件事：旧版 Three.js 依赖是否妨碍维护、指定落点是否在全套骰型上可靠、数字与材质在实际屏幕上是否清楚。若这些检查不通过，再比较 Dice Box 的接入方式或自行构建动画层；现在不提前建设插件系统或完整 3D 引擎。
