# 本地战斗桌

首轮单人 D&D 2024 战斗原型。规则计算、权限筛选和正式存档由本地 Node.js 程序处理；3D 棋盘使用已有骰盘依赖中的 Three.js 0.143.0。日常本机使用可断网；主动开启线上分享时，玩家可见的数据通过Cloudflare连接工具转发。没有模型调用。

目录说明：本模块位于项目/程序/战斗，公共代码在Code，当前核心class-resource-tests-v9。平台新团通过显式建立创建本团独立战斗桌；旧独立入口/存档仍可读取，不自动迁移。完整职业/法术仍按已实现的本地机械范围与DM裁定处理。

## 2026-11-03 战斗画布更新

平台战斗页直接嵌本核心，玩家管理已改为主区页面。新团空白战斗没有默认棋子，使用参战者“＋”新建、复制或从平台资源选取。固定能力MD表格中的明确基础数值可预填，未识别字段为待填占位；所有导入保持未确认。规则占地与模型长宽高分别编辑，NPC与怪物在机械层仍沿用npc类型，外观预设区分显示。

创造搭建：WASD飞行、Space上升、Shift下降，拖动环视或锁鼠；右键放置、左键破坏，Esc退出。1尺/5尺方块及当前积木有透明预览，预览不保存。确认沿用原add/remove-object与undo，支持开战中DM编辑，Player无权限。旧地形几何保留；大块与半尺旧几何不会强制拆档。

模型目录在Code/data/model-catalog.mjs，人物/武器几何在web/voxel-model.mjs，粒子在web/combat-effects.mjs。当前本地40种独立种族与13基础职业组成520种稳定模型，2024核心120种；15种武器家族有各自几何与动作。新增外观可扩目录和组件，不改机械占地。服务端保存成功的公开visualEffect只含可见角色/目标、武器家族及颜色，不包含私密数值；两个视角均可播放，隐藏目标过滤，进入页面不重放历史事件。

从平台资源选择需要平台通过resourceProvider提供只读资料，仅DM接口可用。独立启动没有该资源提供者时仍可新建棋子，界面提示从平台进入资源选择。旧存档无外观字段时沿用默认模型，新增显示字段不改变攻击数值。

## 打开和身份

1. 日常使用[平台主入口](<../../打开平台.cmd>)，在模组窗口载入并确认团后进入战斗。需要单独开发或运行战斗时，双击本目录的[启动战斗.cmd](<启动战斗.cmd>)；它只启动独立战斗核心，复用规则与存档，不需要平台进程。
2. 玩家输入角色名、角色 ID 或 `player-1`，玩家入口按身份展示自己的完整状态及已揭示棋子，控制自己的当前回合。
3. DM直接点击“我是DM”，或输入 `DM`，无需凭据。旧的“查看DM凭据”入口兼容为打开窗口；现有本机身份文件不再读取，也不删除用户已有文件。
4. 首次由 DM 选中每个棋子，打开“角色详情”，核对数值、当前资源与形态、攻击列表，勾选已核对并保存；然后“收集先攻”，全员提交后开始。角色卡的手写抄录只是预填草稿，程序不自动赋予照片中的临时生命。

`http://127.0.0.1:4182`是程序运行时的本机内部地址，不是日常启动入口。核心退出或电脑重启后，单独打开地址不会启动程序。请始终双击本地入口；核心不在运行时会自动启动，确认就绪后再显示窗口。

关闭窗口后进度保留在文件中；强制中断后，再打开同一入口会处理已退出进程留下的标记并读取原文件。DM也可在“更多”中点击“关闭本机程序”停止核心及分享。停止后立即重开时，入口会短暂等待旧进程释放文件锁；启动失败会显示说明，日志在战役目录，不含DM凭据。每次确认操作成功才写入正式文件；未点击保存的输入不算已保存进度。

窗口使用本程序下的专用配置 `.runtime/战斗窗口/`，与平时浏览器资料分开；它是窗口缓存，不是正式战斗存档。找不到可用Edge时回退到默认浏览器，同样仅访问本机。移动整个工作区后，根目录入口仍按相对路径工作。

终端运行方式：

```powershell
node launcher.mjs --no-browser
node launcher.mjs --browser
node launcher.mjs --campaign "战役目录的完整路径" --port 4183
```

需要 Node.js 20 或更新版本，以及同级骰盘目录的 `node_modules/three/`。这些文件均已在本机，无需联网下载才能启动。Three.js的锁定版本仍由骰盘 `package-lock.json` 管理；启动器会核对版本。若主动删除了依赖或移动了部分项目文件，需先恢复完整目录；本模块不自动下载或更新依赖。

玩家名字/ID与DM按钮用于本机视角选择，均无需口令。玩家界面与接口都不返回隐藏单位、敌方精确HP/AC、DM备注、私人事件或完整存档。浏览器会话有效期8小时，服务重启后重新登录。同机使用者可自由切换DM与玩家视角；远程玩家使用绑定角色的邀请，不能切换为DM。

## 团、战斗与日常流程

DM点击顶部“团与战斗”可新建团、新建战斗，并通过两个下拉框选择后点击“打开所选战斗”。新建时明确选择空白资料或复制现有战斗当前状态。各场独立保存HP、资源、棋子、盘面与事件；复制不会把之后的改动回写来源战斗。

DM日常只需这几步：

1. 点“团与战斗”打开本场，点“布置棋子”添加、复制或拖动摆放；选中角色后点“角色详情”核对资料并保存。
2. 在“行动与掷骰”选择程序骰或线下骰，点“收集先攻”。玩家自行提交，DM处理NPC；也可替未提交者掷骰或代填。
3. 齐全后点“开始战斗”。当前行动者自动选中，拖动移动，选择攻击和目标，填入所需骰点或直接让程序掷骰，然后结束回合。
4. 填错的先攻可点“重填”；已完成的操作可点底部“撤销上一步”。特殊效果使用行动区“DM裁定”。

本场完成后，在“更多”中选择“结束本场战斗”。结束画面保留本场资料和记录，显示进度已保存，不再标记当前回合或催促提交先攻；下一场可从“团与战斗”新建。

玩家在同机输入名字/ID，或在自己的设备打开DM给的邀请。需要先攻时就在“行动与掷骰”提交；轮到自己时拖棋子、选攻击并完成骰点，最后结束回合。小屏点右下角“行动与掷骰”打开抽屉。角色原始骰点、自动加值和已保存结果各有提示。

线下骰只填原始d20，优势/劣势填两颗，加值由程序计算。先攻提交后刷新仍在；开始战斗不会重新掷先攻。攻击天然20增加双倍伤害骰输入框；伤害可以先留空，未命中直接完成，命中时提示补齐后再提交，完整攻击只保存一次。程序骰场次也可单独录入某次攻击的线下骰。修改先攻加值、参与者或骰方式后，须重新收集先攻，原记录保留。

界面只常驻棋盘、当前回合、行动与保存状态；资料、记录、主持交接和帮助按按钮打开。关闭工具保留尚未提交的资料草稿；要继续其他写操作，先保存或放弃资料编辑。不同角色的人工裁定输入会清空，避免把上个角色的治疗/伤害误用给下个角色。未提交输入不是正式存档。

## 数值、资源、操作格与玻璃球

操作分类按最新要求：疾走、撤离、躲藏归“移动”，协助归“徒手”；分类只影响查找位置，2024动作费用保持不变。

常规动作含义：回避花动作为自己提供至下回合的防守优势；影响通过交流向NPC提出请求，是否检定及能否接受由主持确定；预备先花动作声明可感知触发和约定响应，响应预备行动则在触发完成后花反应执行；搜索用感知相关技能找隐藏事实，研究用智力相关技能理解或回忆知识。操作详情内列出具体条件。预备施法会当场付资源并维持专注，释放时不重复扣环位；这些条件和特殊效果目前仍由主持核对。

宽屏棋盘右侧并排两栏：偏左的“棋子与资源”放所选角色资料、生命条和资源图标，偏右的“常规操作”按类别列出操作格。两栏顶部箭头可分别收起为窄条，再点箭头展开；折叠不会清除表单。小屏从右下角“行动与掷骰”进入同一套两栏内容，并可用顶部按钮定位。生命条为红色，临时生命条为青绿色；刻度条右侧是当前/上限。移动、法术位和职业资源只在资源区用图标及读数显示。临时生命的分母是本次接受的授予量，受伤不会缩小分母；0/0为空条。AC等无消耗上限的数据用数值徽标。

动作圆形、附赠动作三角形、反应菱形、攻击机会独立列出。普通法术位按环分组，4枚为带间隔的2×2；契约法术位与普通位分别记账。消耗后的符号变灰。较大资源池按32段等比显示，图标旁读数保留完整数量。已用动作但仍有额外攻击时，攻击机会和武器操作仍可用。

点资源打开同色透明玻璃球，中心图标及消耗缺口与资源栏同步。环绕方格有前后景深，支持拖动、滚轮、左右按钮/方向键旋转；进入“法术→环级→具体法术”等下一层，面包屑和Esc逐层返回。每页最多8项，可翻页；也可切为列表。旋转、浏览、排序和取消都不会扣资源。

操作格显示2024通用动作，以及本角色登记的武器、法术、职业特性与装备。各类别完整列出操作，拖动同类方格交换位置；“调整位置”还提供触摸拖动和分类内前后移按钮。顺序按团、身份、角色保存，原有顺序在各分类内继续生效。灰色项仍可打开查看原因，确认按钮会阻止非法使用。

“资源与界面设置”提供：

1. 每种资源的可用色、消耗色，以及透明底PNG/WebP导入。图片在本机归一为96像素纯色遮罩，由配色控制颜色；不加载远程图片或可执行SVG。
2. 球内图标、名称和数量的拖动布局预览，也可填写百分比坐标或恢复默认。
3. 主持核对本场资源的ID、当前量、上限、类型、来源及短休/长休/本人回合恢复量。`all`为全满，整数为恢复该数量，留空不自动恢复。长休不隐含套用短休配置；预掷结果须重新录入。
4. 表单或JSON登记本场法术/特性/物品，填写启用的2024或兼容扩展来源、条件及组合费用。收录资料不等于启用，旧资源备注也不会自动变成职业能力。

武器和疾走直接进入已有本地结算。其他操作明确标为“主持裁定”：主持核对触及、体型、成分、触发、检定/豁免、专注及最终效果，再确认费用与伤害/治疗/临时生命等结果。一次提交整体成功才扣费、写文件，可撤销；不会凭法术名字自动推算全部效果。玩家可生成提议交给主持，不能自行应用DM裁定。若局面在填写期间更新，须重新选择操作，旧提议不能覆盖新状态。

采用2024费用：普通跳跃花移动预算；推撞/擒抱是徒手打击分支，使用攻击机会；轻型额外攻击、Nick等须登记具体能力。蘸取/涂层按物品目录的具体用途核对，不能直接套用BG3的附赠动作或伤害。每回合最多消耗一个法术位，普通与契约位共同计数；反应在本人回合开始恢复。资源有余量不等于当前可操作；尚未轮到时仍显示真实余量，操作确认按回合限制。上一回合动作、攻击和移动余额以只读回合记录展示，不参与第二套结算。短/长休由主持在战斗结束后明确记录，仅恢复配置的资源；其他休息效果仍须核对。关窗口、刷新或切换战斗不会自动回满。

资源池保存在各场`战斗状态.json`的`actors[].resourcePools`，操作保存在`actors[].operations`。旧存档新增显示基准和默认空池前会保留升级前原件，不猜测真实角色的职业或数值。界面配色、图片、布局及排序存于工作区`界面设置.json`，按团与身份隔离，不占战斗版本与撤销历史。无效设置文件会保留原件并显示恢复提示；不支持的较新版本不会被覆盖。备份时请一并保存整个存档目录。

## 物品目录、个人与团队背包

左栏资源区点“背包”，可查看选中角色的个人背包、本场团队背包或全部2024物品目录，并按名称/类别搜索。目录集中在 `data/items-2024.mjs`：共182个具体条目，覆盖PHB2024冒险装备及弹药、法器/圣徽变体、武器、护甲盾牌、工匠和其他工具，包含具体赌具与乐器。坐骑、载具、服务、钱币及其他扩展魔法物品未混入。每项带规则版本、来源路径、用途及费用；看到目录条目不代表已经持有它。

“操作”“投掷”“蘸取／涂层”“饮用／喂治疗药水”会打开物品选择，列出对应用途的个人和团队库存。默认只显示持有物品；取消“只显示”可查看无库存的目录项，但不能免费使用。一个物品可能具有多种用途，实际费用以选中的用途为准，不额外叠加入口的默认动作。例如：

| 用途 | 2024费用及处理 |
| --- | --- |
| 饮用或喂治疗药水 | 附赠动作、1瓶；本地掷 `2d4+2` 并治疗，喂药目标须在同高5尺内，也可自饮 |
| 涂基础毒药、饮用抗毒剂 | 附赠动作、1瓶；涂层目标、触发和中毒相关效果由DM核对 |
| 投强酸、炽火胶、圣水、燃油或捕网 | 替换攻击动作中一次攻击；距离、豁免、目标类型、后续状态等由DM裁定 |
| 撒滚珠／铁蒺藜、使用医疗包 | 操作动作；范围、稳定伤势及其他条件由DM核对；医疗包每次扣1次使用 |
| 护甲穿卸、特定工具或其他用途 | 依目录区分动作、附赠动作、攻击机会或须核定时长的手工用途；不统一扣一个动作 |

治疗药水可用程序骰，或勾选实体骰后录入两颗原始d4点数，例如 `3，4`，本地算出9点治疗并限制到最大HP。本场为线下骰模式时必须录入原始点，不代掷。费用、库存和HP同一事务保存，失败不会部分扣除；重试、撤销、版本与操作ID继续使用原有保护。玩家目前只可在战斗内使用自己的自动治疗物品；复杂用途须交DM确认，玩家可生成提议供主持核对。

团队库存属于本场快照。使用团队物品还须DM明确勾选“当前可取用”；拥有或看见它不代表它就在角色身边。个人与团队库存择一扣除，不同时扣两份。战斗中按用途扣回合费用；战斗外仅DM可确认使用，记录依据后不扣回合动作。目录中的 `manual` 用途须DM明确填核定费用数组，非战斗中只能填空费用，不自动推进分钟数或模拟工作过程。

除治疗药水外，物品效果需填写裁定依据与明确结果；程序不凭物品名称补出豁免、持续状态、陷阱触发或地形。伤害JSON填写减免前的分类伤害；外部已处理过抗性等减免时可填写最终HP，避免再次减免。普通蘸火不会自动获得BG3式额外伤害。仅供查看的 `reference` 用途可转到“主持手动记录”，默认只记日志，不自动扣库存或行动；若确实需要改变数量，由DM另行核对背包。

主持展开“修改库存”，可添加物品或编辑个人/团队背包JSON，填写修改依据后保存。JSON保留载入时的进度版本，期间局面更新则须重新载入核对，不会覆盖新进度。库存结构如下：

```json
[
  {"id":"potion-stack","itemId":"phb24-gear-potion-of-healing","quantity":2},
  {"id":"medical-stack","itemId":"phb24-gear-healer-s-kit","quantity":2,"charges":4}
]
```

条目ID在各背包内唯一，`itemId`引用目录，`quantity`为0～9999的整数。医疗包每件10次：`quantity:2, charges:4`表示当前包余4次，另一包完整10次；未填`charges`表示当前是新包。扣尽当前包后移至下一满包，全部耗尽变为数量0、次数0。多个已打开的包须拆成不同条目。投出的武器/捕网、撒出的滚珠等数量移出表示离开当前持有库存，不宣称物品永久毁坏；回收另由主持核对。目录里有武器、护甲或法器不等于已装备，也不会自动增加AC或授予熟练、受训、精通及同调。

个人库存保存为 `actors[].inventory`，团队库存保存为 `partyInventory`。它们随本场快照、撤销和重启保存，不把之后的改变写回角色资料库或其他战斗。玩家只能接收自己的个人背包与本场团队背包，不能读取他人的私有库存；全部公开物品目录不受此限制。

48个PHB2024子职的20级资源预设分两场：`test1`保留原角色并加野蛮人、诗人、牧师、德鲁伊、战士、武僧各四子职共24个；`test1-子职测试2`放圣武士、游侠、游荡者、术士、魔契师、法师各四子职共24个。两场团队背包各含182项目录库存，个人持有不同物品。先从“团与战斗”切换，再选中角色查看图标、操作格和背包。

这些角色默认未确认；HP100、AC15与训练攻击是合成占位，不能直接当完整合法角色卡或平衡遭遇。左侧资源下的“20级资源测试说明”列明条件恢复、待补选择和特殊标记。资源额度/环位可按统一操作扣除，预兆必须先真实掷骰再登记；结界创建、专注、宠物、形态、每回合限制及临时创造法术位等仍由主持核对。嵌套manualState的更新需本地JSON预览刷新或主持备注，当前不会自动执行其全部效果。

预设维护在 `src/testing-presets.mjs`。仅DM、准备阶段可通过统一 `add-testing-actors {batch:1|2}` 生成整批24人，重复身份、容量超过40或无足够空位时整批拒绝；不接受客户端自带角色数组，不改原角色和原库存数量。每次导入为缺失目录物品补入5件，医疗包每包10次；导入可撤销。

## 方块人物、拖动与搭地图

“行动与掷骰”现在所有窗口尺寸都可见；宽屏会展开并定位偏左右栏，窄屏打开抽屉。战前待办列出尚未核对、起始HP不合适或未提交先攻的具体角色，点角色按钮直接核对；必须点保存，单独勾选不算完成。

DM选中棋子 → 角色详情 → “方块人物与装备外观”，可选方块人/长方体、人形/巨人/怪物配色，以及剑、斧、棍棒、弓、盾和分部位盔甲。尺寸沿用外观长宽高；规则占地独立。装备是自制Minecraft风格几何，全部离线显示，换装备外观不会增加AC或改写攻击列表。

点“地形”打开搭建工具：

1. 选择矩形/圆形/三角形地板，或1尺/5尺方块、坡块；工具会开启“连续放置”。左键在棋盘上单击，每次添加同类物件。取消勾选或按Esc停止连续放置。
2. 停止连续放置后，直接拖动已有物件；打开地形工具时优先选物件，可切换“仅地形”或“仅地图地板”，避免遮挡。关闭工具后恢复棋子点选与拖动。
3. 拖动中按 **Shift** 只改变 **Z轴（前后）**，保持X及Y高度；按 **Ctrl** 拖动地形/地图物件会复制副本。棋子战斗移动不支持Ctrl复制。
4. 多选列表中用Ctrl/Shift选择数件，再点“编组”；拖组中任一件会整体移动。“拆组”恢复独立物件。拼贴保留独立几何，不是不可逆地合并成一个模型。
5. 按需选择1尺/5尺网格、边缘贴合、顶面高度对齐。关闭吸附仍以0.5尺保存精确坐标。旋转目前为90度步进；具体坐标、尺寸与高度可在表单修改。

延伸网格随镜头显示，支持负坐标和原盘面边缘外布置。首次打开旧存档会先备份，再启用延伸布置；也可取消该开关恢复矩形边界限制。原矩形底板可隐藏，使用地图地板拼出新形状。辅助网格不是实体地面：拼贴区域、空洞、非矩形碰撞、高差和楼梯通行由DM裁定；原底板内的基础矩形阻挡继续自动检查。系统遇到可能涉及这些情况的自动移动会暂停，不把包围盒当成精确规则。

当前编辑范围为X/Z正负10000尺、高度0～100尺，单场最多2000件物件，一次编组/移动/复制最多200件。动态网格不保存成无限实体；数量上限不等于所有电脑都能流畅显示满额，建议分场景建立战斗。落点预览不写文件，松手后成功才保存；Esc取消，已保存操作可撤销。

## 本地JSON文件与刷新

DM点底部 **本地文件**。提供打开本团文件夹、在资源管理器中选中玩家/NPC资料文件或本场战斗JSON的按钮，显示文件路径与修改时间。资料库首次打开时从本场建立，之后不自动覆盖你的编辑。

- `玩家资料.json`、`NPC资料.json`：团级可复用角色资料。外部编辑器保存后点“刷新文件列表”，选角色、“预览此角色资料 → 本场”，核对差异后应用。保留本场位置和朝向，数值及装备等资料更新到本场；其他战斗不变。资料里的角色必须已在本场且ID/归属一致，添加参战者仍用“布置棋子”。
- `战斗状态.json`：本场正式快照，包含当前角色HP、回合、地图、事件等。外部保存后点“预览并刷新本场JSON”，核对后“应用已核对的文件差异”。程序检查内容、团和战斗标识、角色归属及版本，产生新版本并保留历史和撤销。不要手改ID、格式版本或进度版本；不要用旧战斗文件覆盖正在进行的局面。
- 普通刷新按钮只读取服务端状态；文件重载须经过上面的预览。检测到战斗JSON外部变化时，行动区出现提示，后续写操作拒绝覆盖文件。坏JSON、非法值或预览后文件又变动都会停止应用，保留原件及有效内存；修正文件后重新预览。

角色资料库不随战斗扣血自动变化，本场实际进度以战斗JSON为准。外部重载前保存`外部编辑-<ID>.json`原件及上一有效状态；程序内撤销保留原骰点与操作记录。编辑JSON时避免与其他玩家同时行动。文件定位和完整JSON仅本机DM可用，远程玩家仍只接收过滤后的局面。

## 面对面与线上加入

点顶部“联机”，然后：

- 同一个Wi-Fi：点“开启同Wi-Fi联机”，选择角色，点“生成并复制邀请”，将完整链接交给对应玩家。
- 不同地点：点“开启线上联机”，等待显示“线上可加入”，再选择角色并复制邀请。朋友只需浏览器。
- 邀请生成后也能手动复制。同一个角色重新生成邀请会使旧邀请失效；点“撤销邀请”可收回某个角色的访问，点“关闭分享”结束全部联机。

主持电脑须保持程序运行。正式进度始终在主持电脑文件里；玩家断线后会暂停提交、自动尝试重连，不重放旧操作。切换战斗、停止分享或重启程序后重新邀请。默认不开分享；同一时刻开放当前一场战斗。已连接人数按近期活动统计。

局域网地址含本机网络地址和自动分配端口，IP变化后重新开启并复制。访客Wi-Fi可能隔离设备；Windows若提示网络访问，按自己网络情况允许可信私人网络。程序不会自动修改系统防火墙、代理、路由器或开机启动项。

线上使用官方 [Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)，不需要账号或域名。连接地址会变化，关分享后失效，没有可用时间保证；本地固定启动入口不变。仅转发玩家入口，不开放DM管理、存档文件、角色原图或资料目录。邀请链接相当于该角色的通行凭证，只交给对应玩家。

已在本机准备 `.tools/cloudflared.exe`，固定为2026.10.4，来自 [官方发布](https://github.com/cloudflare/cloudflared/releases/tag/2026.10.4)，SHA-256为 `411b16d40c8d872243efeb52c550053d00af0a8a97fbb32e730fb8aba429eaa8`。工具不进入Git、不自动更新，只在点线上联机时运行。移动整个项目可一起保留；仅从Git恢复源码时需从同一官方发布下载并核对校验值，放回该位置。工具缺失不影响本机与同Wi-Fi玩法。

默认工作区为 `项目/模组/工作区.json`，记录团列表和最后打开的战斗。每团的兼容权威根为 `项目/模组/<团目录>/战斗/存档/`，其中有 `团资料.json`、第一场 `战斗状态.json`、原角色卡/怪物资料，后续场次位于该权威根内的 `战斗/<战斗ID>/战斗状态.json`。独立战斗新团外层使用 `团-<ID>`，故事/对话与战斗并列。旧格式首次升级前保留逐字节原件 `格式迁移前-<ID>.json`。备份时停止服务并复制整个项目，保留模组索引和资源引用；旧布局备份仅供恢复。用 `--campaign` 单独指定测试目录时默认索引在该目录 `.工作区/`，也可用 `--workspace` 指定。

## 棋盘和操作

大格5尺，小格1尺。拖动自己的棋子完成移动，DM战前拖动是摆放；拖动空地旋转；右键拖动平移，Shift+左键拖空地也可平移（拖物件/棋子时Shift锁定Z轴）；滚轮缩放。先点击棋盘使其获得键盘焦点，再用 `Q/E` 或左右键旋转，`R/F` 或上下键调倾角，`W/A/S/D` 平移，`+/-` 缩放，`0` 复位。右下角也有缩放和复位按钮。

点击棋子或棋盘上方名单选择它。拖动时显示吸附落点，松手才校验和保存；Esc、失焦或局面更新会取消预览。超速、越界或路径受阻时回原位并提示。精确位置仍可手动输入。初始/复位镜头按窗口比例适配完整盘面。

长方体外观宽、深、高可以修改；程序比较三组相对面面积，将最大的一组标为金色“前”与深色“后”（同面积依次选Z、X、Y法向）。尺寸代表显示占位值，不声称是角色精确体测。朝向只旋转外观；地面占地不随朝向旋转。地面线框表示规则占地，与长方体外观分开。

常规移动拖动棋子或展开“输入移动位置”填写目标X/Z后执行，按5尺格结算：横移、直移或斜移一格均消耗5尺，能拆分移动，疾走消耗动作并增加一倍速度的移动额度。起始棋子对齐格心。1尺线用于观察；DM位置编辑可做0.5尺精细定位且不消耗移动力。地形编辑中勾选实体阻挡的物件会阻止穿行；穿过生物占地的合法性和移动费用尚未完整实现，程序拒绝这种直线路径，需分段绕行或人工裁定。

## 盘面与地形

DM打开回合栏“地形”：先改盘面宽/深并保存，再选墙、隆起、楼层平台、楼梯或道具，填中心X/Z、底部高度Y、宽/深/高后添加。下拉列表可选已有物件，修改、复制或移出；勾选点击空地移动可在棋盘定位。全部经过规则入口保存，可撤销。每场最多2000件；原矩形底板宽深20～300尺，延伸布置可使用正负10000尺范围，保持5尺大格/1尺小格。旋转首版使用0/90/180/270度，尺寸及位置对齐0.5尺。关闭延伸布置后，缩小盘面若使棋子或物件越界，会拒绝保存。

二楼示例：平台Y=9、高=1，角色脚底Y=10；三楼平台Y=19、高=1，角色脚底Y=20。角色高度在“战前布置”或资料编辑中设置，外观整体和占地线框随之抬高。楼梯沿本地Z方向从低到高，旋转可改方向；隆起为分层几何块。对玩家隐藏的物件不进入玩家数据和3D场景。

自动阻挡采用角色规则占地扫过轴对齐物件包围盒，连续检查薄墙，不允许穿透；竖向只用当前外观高度作保守范围检查。高处移动、楼梯通行、高差攻击及地形可能影响的攻击线路均暂停并交DM明确裁定。生物占地自动比较同一脚底高度，未实现完整三维碰撞、寻路、承重、坠落、掩护或视线判断。DM核对后用位置编辑调整高度/位置，并在资源或人工裁定中记录移动消耗与依据。

当前可直接使用本地几何积木。素材候选为 [Kenney地牢](https://kenney.nl/assets/modular-dungeon-kit)、[城堡](https://kenney.nl/assets/castle-kit)、[家具](https://kenney.nl/assets/furniture-kit)，官方包页均标CC0。本轮仅调研，未下载或接入模型导入器。后续以本地GLB/glTF替换显示，另存素材来源、许可、尺寸与脚底锚点；规则占地和阻挡形状继续由本地数据决定。完整调研在工作区产品大纲。

## 自动结算范围

- 先攻按加值掷d20；`start.payload.modes` 可指定参与者的优势/劣势（如突袭）。同分暂按DM设置的优先级排列；首轮未操作时可用 `set-order` 调整同分顺序。
- 每个参与者轮流行动，动作、已用攻击次数和移动距离在下一回合重置。NPC 的目标、攻击和战术由 DM 选择。
- 普通近战/远程攻击检查当前回合、控制权、触及/射程、动作和次数。攻击加值、伤害公式须由DM核对；不自动替角色选武器或法术。怪物的多重攻击逐次结算。
- 天然1自动失手，天然20自动命中；重击翻倍伤害骰，固定加值只加一次。支持常见D&D骰型、优势/劣势、远射程劣势与可见敌人5尺内的远程劣势。其它优势、失能、可见性和状态由DM判定；当前简单对抗以玩家角色/NPC区分敌我。
- 按同次攻击的伤害类型合并分项后计算免疫、抗性（向下取整）、易伤；先扣临时生命再扣HP。治疗不会恢复临时生命，赋予临时生命不会叠加；表单保留较高值，如需主动舍弃旧值，可用DM设置明确覆盖。
- 生命归零后，死亡豁免、死亡、变形结束和额外伤害不自动执行。针对已归零目标的自动攻击会暂停，交由DM裁定。下一回合不会自动替倒地角色行动。

复杂法术的完整效果、荒野形态完整替换、专注、借机攻击具体条件、掩护、视线/自动迷雾、飞行与高差、困难地形、状态时限等仍须DM裁定。已登记的法术位/职业资源费用、反应次数、库存消耗及治疗药水已有本地结算；这不等于所有职业特性或物品效果已自动化。DM在人工裁定中填写依据、明确数值与公开结果，并核对效应到期。分类伤害输入的是减免前分项，程序继续处理所设免疫/抗性/易伤；已在外部结算过的结果用最终HP记录，避免重复处理。

所选怪物归档资料在战役目录，DM可在“原始资料与出处”查看完整结构数据。原图与草稿可通过战役目录的 `开始检查.html` 对照；这轮不承诺完整12级月德的自动战斗，也未验证此遭遇的难度平衡。

## 文件、保存和恢复

默认战役由 `项目/模组/工作区.json` 的活动选择确定，路径指向该团的 `战斗/存档`。没有有效活动团时提示从平台模组窗口选择，不猜目录；合成检查仍可显式指定 `--campaign`。

| 文件 | 用途 |
| --- | --- |
| `角色卡/`、`怪物/`、`资料清单.json` | 原件、待核对抄录和资料来源 |
| `战斗状态.json` | 正式局面、角色、资源、DM秘密、事件与已执行操作ID |
| `战斗状态.previous.json` | 上一次已确认的完整进度 |
| `本机身份.json`（历史文件） | 当前版本不再读取或生成，原有文件保留 |
| `团资料.json` / `工作区.json` | 团内战斗列表 / 工作区团列表与最后打开位置 |
| `objects`（战斗状态内） | 每场物件的稳定ID、类型、尺寸、位置、朝向、可见性与阻挡属性 |
| `actors[].inventory` / `partyInventory`（战斗状态内） | 各角色个人背包 / 本场团队背包，包含目录物品ID、数量及适用的单件使用次数 |
| `.battle.lock` | 防止两个进程同时写同一战役；正常停止后自动释放 |
| `损坏存档-时间.json` | 当前文件损坏时保留原件，再从有效备份恢复 |

每个操作先检查团ID、战斗ID、唯一操作ID、期望版本、权限和规则，再串行提交：保存上次完整状态，写入临时文件并同步磁盘，最后替换正式文件。Windows短暂占用文件时仅重试同一替换，最多等待500毫秒，不重复结算。最终写入失败不提交内存状态、不显示成功；重试前请刷新核对。主文件不可用时从有效备份恢复并在页面提示；必须核对最后一次操作是否需要补做。版本不支持或两份文件均不可用时，停止启动并保留原件。

所有战役文件、资料全文及测试输出均排除出Git。**源码Git保存点不能恢复私人进度。**要保留长期战役备份，请先停止本地服务，将整个战役目录复制到自己的备份位置，再重新启动。需要回到上一次进度时，先备份当前整个目录，在停止服务时用 `战斗状态.previous.json` 的副本替换主文件；不要删除唯一原件。工作区及团索引有各自的previous备份；索引损坏会停止打开并保留文件，需停止服务后人工核对恢复，不会擅自创建空团。每场战斗另保留最近30项操作的撤销快照。界面撤销是一次新的保存，保留原骰点、已执行ID与撤销标记，不会重新掷骰；旧提议会因版本变化被拒绝。撤销不能替代整目录备份。

## 主持交接与扩展

“生成局面包”取得 `local-dm-exchange-v2` JSON，包含明确的 `audience`、局面、版本及操作模板。手动复制给GPT、Workbuddy或人工；是否向外发送私人信息由使用者决定。本机页面不会自动调用模型或把局面包交给外部聊天工具。返回 JSON 后粘贴，点击“预览提议”核对，再“确认执行已预览提议”，或者调用同一 `/api/action`。目前只验证人工交换，不承诺现有外部工具的自动控制接口。

操作信封示例（ID与版本必须来自当前局面包）：

多团API（DM）：`GET /api/catalog`，`POST /api/select {campaignId,battleId}`，`POST /api/campaigns {name,copyCurrent}`，`POST /api/battles {name,templateBattleId?}`。攻击计划 `POST /api/attack-plan` 只返回所需骰型/颗数，不掷骰或暴露敌方数值；攻击可附 `manualRolls:{attack:[原始d20],damage:[[各项伤害骰]]}`。

API：`POST /api/login` 输入 `{id}` 得到会话令牌（DM的id为`DM`，均无需口令），后续使用 `Authorization: Bearer <token>`；`GET /api/state`、`GET /api/handoff`、`POST /api/action`、`POST /api/logout`、DM专用 `POST /api/shutdown`。上述本机入口只接受本机Host及同源浏览器请求，启动器同时核对核心版本与工作区，避免旧核心或另一工作区被误复用；不提供文件系统通配访问。调用本机HTTP接口不需要模型服务。

分享API仅本机DM：`GET /api/sharing`查看状态，`POST /api/sharing {operation}`开启/关闭/邀请；operation为`enable,disable,invite,revoke,start-online,stop-online`，邀请附actorId，撤回附inviteId。独立玩家入口只开放静态界面、`/api/client-info`、`/api/join {invite}`及玩家态state/action/attack-plan/handoff/logout/preferences。邀请经链接片段传入，在页面换会话后从地址栏移除；玩家和本机令牌互不通用。短轮询只读最新状态，所有写入仍经同一事务队列和版本检查。

全部可执行操作、基础掷骰、权限及局面投影集中在 `src/operations.mjs`，`src/rules.mjs`只保留旧导入兼容。`src/action-catalog.mjs`管理界面操作目录；`data/items-2024.mjs`是Node与浏览器共用的物品事实/用途单文件，`src/inventory.mjs`负责库存校验、选择与扣除。界面由`web/inventory-panel.mjs`提供背包/物品选择，`web/manual-record-panel.mjs`提供主持记录；两者仍提交统一操作信封，不在界面另做一次机械结算。

其余职责分别为 `src/store.mjs`（原子持久化、外部编辑与串行事务）、`src/workspace.mjs`（团和战斗索引/切换）、`src/campaign.mjs`（资料载入）、`web/board.mjs`与`web/terrain-view.mjs`（显示）、`web/app.mjs`（交互）、`web/shell.mjs`（工具与自适应布局）、`src/sharing.mjs`（玩家接入）、`src/tunnel.mjs`（线上连接工具）。新增物品可补目录用途，具体效果在统一操作文件实现或明确留给主持；个人/团队权限、费用与存档仍走同一入口。后续主持适配器只交换局面与提议；换棋子模型无需改规则占地。存档格式及规则范围都有版本标识；不支持的新版本会拒绝载入。当前事件写在单一JSON内，长战役时按实测评估体积后再拆日志，未引入数据库。

文件API仅本机DM：`POST /api/files`始终携带当前`campaignId,battleId`，operation为`list,reveal,preview-battle,reload-battle,preview-library,apply-library`。reveal仅接受players/npcs/battle/folder登记键；应用预览携带`fingerprint,expectedRevision`，资料应用另附`key,ids`。不支持任意路径、命令或远程文件访问。

扩展职责：`web/voxel-model.mjs`只生成外观，`src/map-placement.mjs`只计算对齐，`src/local-files.mjs`负责资料库与已登记路径，`src/store.mjs`检测外部修改和提交重载；核心规则仍负责最终校验。拼贴物件保持独立ID，未来可增加材质或精确碰撞而无需替换整个存档系统。

## 主持手动记录与统一操作代码

全部可执行操作及基础掷骰入口集中在 `src/operations.mjs`，`src/rules.mjs`保留旧导入兼容；`src/action-catalog.mjs`负责界面可用目录。资源和库存的纯数据校验仍由对应模块协助，界面不另做结算。新增命令仍通过 `/api/action`、版本、权限、重复ID和原子存档校验。

左栏DM工具打开“主持记录与通用掷骰”：通用骰输入公式、用途与来源，人工模式只填原始点，本地计算总数；优势/劣势仅用于一颗d20检定。仅记录是默认模式，保存外部已经发生的事实和骰点，不再掷骰、扣资源或修改生命。记录并应用须明确填写目标、数值与费用，再预览确认；伤害填减免前分类值，外部已核定的结果填最终HP及可选最终临时生命，避免重复减免。费用从所选行动者扣，结果应用到目标。公开说明留空则为DM私密日志。局面变化须重新预览，撤销保留原审计。

接口：roll-dice {actorId?,label,formula,mode?,values?,origin?,note?,publicNote?}；人工来源origin为physical-dice/external-tool/dm-recorded。manual-record {mode:record-only/apply,actorId?,targetId?,label,note,rolls:[{formula,values,origin,mode?}],application?,publicNote?}；application允许heal、减免前damage、finalHp、temporaryHp授予量、finalTempHp最终余额和costs数组。finalHp不与damage/heal混填；finalTempHp不与damage或temporaryHp混填。角色/战斗ID和操作版本仍在统一envelope中。通用掷骰本身只记录，不自动代表攻击、伤害或消耗行动。
