# 本地战斗桌

首轮单人 D&D 2024 战斗原型。规则计算、权限筛选和正式存档由本地 Node.js 程序处理；3D 棋盘使用已有骰盘依赖中的 Three.js 0.143.0。无需安装新依赖，无模型调用或外部网络请求。

## 打开和身份

1. 双击工作区最外层的 [打开跑团.cmd](../../打开跑团.cmd)，或本目录的 **打开跑团.cmd**。程序自动启动本地核心、读取原存档，默认用已安装的Edge打开独立应用窗口；不需互联网，重复打开会复用同一战役核心。
2. 玩家输入角色名、角色 ID 或 `player-1`，玩家入口按身份展示自己的完整状态及已揭示棋子，控制自己的当前回合。
3. DM直接点击“我是DM”，或输入 `DM`，无需凭据。旧的“查看DM凭据”入口兼容为打开窗口；现有本机身份文件不再读取，也不删除用户已有文件。
4. 首次由 DM 选中每个棋子，展开“资料与棋子设置”，核对数值、当前资源与形态、攻击列表，勾选已核对并保存；然后“投先攻·开始”。角色卡的手写抄录只是预填草稿，程序不自动赋予照片中的临时生命。

`http://127.0.0.1:4182`是程序运行时的本机内部地址，不是日常启动入口。核心退出或电脑重启后，单独打开地址不会启动程序。请始终双击本地入口；核心不在运行时会自动启动，确认就绪后再显示窗口。

关闭窗口后进度保留在文件中；强制中断后，再打开同一入口会处理已退出进程留下的标记并读取原文件。DM也可点击“停止服务”彻底停止核心。启动失败会显示说明，日志在战役目录，不含DM凭据。每次确认操作成功才写入正式文件；未点击保存的输入不算已保存进度。

窗口使用专用配置 `项目/存档/战斗窗口/`，与平时浏览器资料分开；它是窗口缓存，不是正式战斗存档。找不到可用Edge时回退到默认浏览器，同样仅访问本机。移动整个工作区后，根目录入口仍按相对路径工作。旧的 `启动战斗.cmd` 也继续可用。

终端运行方式：

```powershell
node launcher.mjs --no-browser
node launcher.mjs --browser
node launcher.mjs --campaign "战役目录的完整路径" --port 4183
```

需要 Node.js 20 或更新版本，以及现有 `项目/骰盘/node_modules/three/`。这些文件均已在本机，无需联网下载才能启动。Three.js的锁定版本仍由骰盘 `package-lock.json` 管理；启动器会核对版本。若主动删除了依赖或移动了部分项目文件，需先恢复完整目录；本模块不自动下载或更新依赖。

玩家名字/ID与DM按钮用于本机视角选择，均无需口令。玩家界面与接口都不返回隐藏单位、敌方精确HP/AC、DM备注、私人事件或完整存档。浏览器会话有效期8小时，服务重启后重新登录。同机使用者可自由切换DM与玩家视角；当前不是联网多人权限系统。

## 团、战斗与日常流程

DM入口顶部可新建团、新建战斗，并通过两个下拉框选择后点击“打开所选战斗”。新建时明确选择空白资料或复制现有战斗当前状态。各场独立保存HP、资源、棋子、盘面与事件；复制不会把之后的改动回写来源战斗。

DM：选团/战斗 → 左侧“战前布置”新增或复制参战者 → 点击棋子后填坐标，或勾选点击空地摆放 → “核对/编辑选中棋子”填写资料并确认 → 选择程序骰/线下骰 → 投先攻开始。新建/复制棋子均需重新核对；规则占地重叠不能开始。战斗期间使用右侧规则移动/攻击；特殊规则用人工裁定，完成后结束回合，全部结束后保留本场并新建下一场。

玩家：输入自己角色的名字或ID → 选自己的棋子 → 等自己的回合 → 右侧移动、选攻击和目标 → 结束当前回合。玩家不能摆局或控制NPC。主持切换到另一场战斗时，旧玩家会话会退出，重新选择身份后进入新场。

线下骰：DM选择“录入线下骰”，在先攻设置中为每位角色填原始d20（优势/劣势填两颗）。攻击时填d20及各项伤害骰，程序计算加值、命中与伤害；天然20自动加出双倍伤害骰输入框。程序骰场次也可仅为某次攻击勾选实体骰。错误/缺失输入不会提交这次攻击，撤销保留原记录。

默认工作区为 `项目/存档/工作区.json`，仅记录团列表和最后打开的战斗。每团有 `团资料.json`；第一场保留团根目录的 `战斗状态.json`，后续在 `战斗/<战斗ID>/战斗状态.json`。原角色卡/怪物文件仍在原团目录。新团放在 `项目/存档/团-<ID>/`。旧格式首次升级前保留逐字节原件 `格式迁移前-<ID>.json`。备份时停止服务并复制整个 `项目/存档/`，其中有跨团索引、各场进度及资料。用 `--campaign` 单独指定测试目录时默认索引在该目录 `.工作区/`，也可用 `--workspace` 指定。

## 棋盘和操作

大格5尺，小格1尺。左键拖动旋转；右键或 Shift+左键拖动平移；滚轮缩放。先点击棋盘使其获得键盘焦点，再用 `Q/E` 或左右键旋转，`R/F` 或上下键调倾角，`W/A/S/D` 平移，`+/-` 缩放，`0` 复位。右下角也有缩放和复位按钮。

点击棋子或左侧名单选择它。长方体外观宽、深、高可以修改；程序比较三组相对面面积，将最大的一组标为金色“前”与深色“后”（同面积依次选Z、X、Y法向）。尺寸代表显示占位值，不声称是角色精确体测。朝向只旋转外观；地面占地不随朝向旋转。地面线框表示规则占地，与长方体外观分开。

常规移动填写目标X/Z后执行，按5尺格结算：横移、直移或斜移一格均消耗5尺，能拆分移动，疾走消耗动作并增加一倍速度的移动额度。起始棋子对齐格心。1尺线用于观察；DM位置编辑可做0.5尺精细定位且不消耗移动力。地形编辑中勾选实体阻挡的物件会阻止穿行；穿过生物占地的合法性和移动费用尚未完整实现，程序拒绝这种直线路径，需分段绕行或人工裁定。

## 盘面与地形

DM打开顶部“盘面与地形”：先改盘面宽/深并保存，再选墙、隆起、楼层平台、楼梯或道具，填中心X/Z、底部高度Y、宽/深/高后添加。下拉列表可选已有物件，修改、复制或移出；勾选点击空地移动可在棋盘定位。全部经过规则入口保存，可撤销。每场最多250件；盘面20～300尺，保持5尺大格/1尺小格。旋转首版使用0/90/180/270度，尺寸及位置对齐0.5尺。缩小盘面时若棋子或物件越界，会拒绝保存。

二楼示例：平台Y=9、高=1，角色脚底Y=10；三楼平台Y=19、高=1，角色脚底Y=20。角色高度在“战前布置”或资料编辑中设置，外观整体和占地线框随之抬高。楼梯沿本地Z方向从低到高，旋转可改方向；隆起为分层几何块。对玩家隐藏的物件不进入玩家数据和3D场景。

自动阻挡采用角色规则占地扫过轴对齐物件包围盒，连续检查薄墙，不允许穿透；竖向只用当前外观高度作保守范围检查。高处移动、楼梯通行、高差攻击及地形可能影响的攻击线路均暂停并交DM明确裁定。生物占地自动比较同一脚底高度，未实现完整三维碰撞、寻路、承重、坠落、掩护或视线判断。DM核对后用位置编辑调整高度/位置，并在资源或人工裁定中记录移动消耗与依据。

当前可直接使用本地几何积木。素材候选为 [Kenney地牢](https://kenney.nl/assets/modular-dungeon-kit)、[城堡](https://kenney.nl/assets/castle-kit)、[家具](https://kenney.nl/assets/furniture-kit)，官方包页均标CC0。本轮仅调研，未下载或接入模型导入器。后续以本地GLB/glTF替换显示，另存素材来源、许可、尺寸与脚底锚点；规则占地和阻挡形状继续由本地数据决定。完整调研在工作区产品大纲。

## 自动结算范围

- 先攻按加值掷d20；`start.payload.modes` 可指定参与者的优势/劣势（如突袭）。同分暂按DM设置的优先级排列；首轮未操作时可用 `set-order` 调整同分顺序。
- 每个参与者轮流行动，动作、已用攻击次数和移动距离在下一回合重置。NPC 的目标、攻击和战术由 DM 选择。
- 普通近战/远程攻击检查当前回合、控制权、触及/射程、动作和次数。攻击加值、伤害公式须由DM核对；不自动替角色选武器或法术。怪物的多重攻击逐次结算。
- 天然1自动失手，天然20自动命中；重击翻倍伤害骰，固定加值只加一次。支持常见D&D骰型、优势/劣势、远射程劣势与可见敌人5尺内的远程劣势。其它优势、失能、可见性和状态由DM判定；当前简单对抗以玩家角色/NPC区分敌我。
- 按同次攻击的伤害类型合并分项后计算免疫、抗性（向下取整）、易伤；先扣临时生命再扣HP。治疗不会恢复临时生命，赋予临时生命不会叠加；表单保留较高值，如需主动舍弃旧值，可用DM设置明确覆盖。
- 生命归零后，死亡豁免、死亡、变形结束和额外伤害不自动执行。针对已归零目标的自动攻击会暂停，交由DM裁定。下一回合不会自动替倒地角色行动。

复杂法术、法术位、荒野形态完整替换、专注、反应、借机攻击、掩护、视线/自动迷雾、飞行与高差、困难地形、状态时限、充能均未自动化。DM在人工规则裁定中填写依据、明确治疗/临时生命/伤害数值与公开结果；需要扣法术位或记录效应到期时，同时更新资源栏。人工伤害输入的是已决定的原始分项，程序继续处理所设伤害免疫/抗性/易伤。特殊规则若改变这些处理方式，由DM先核对并显式调整，不假装已经支持。

所选怪物归档资料在战役目录，DM可在“原始资料与出处”查看完整结构数据。原图与草稿可通过战役目录的 `开始检查.html` 对照；这轮不承诺完整12级月德的自动战斗，也未验证此遭遇的难度平衡。

## 文件、保存和恢复

默认战役在 `项目/存档/单人-12级开卡-<角色名>/`。没有唯一匹配目录时启动器要求 `--campaign`，不会擅自挑一个。

| 文件 | 用途 |
| --- | --- |
| `角色卡/`、`怪物/`、`资料清单.json` | 原件、待核对抄录和资料来源 |
| `战斗状态.json` | 正式局面、角色、资源、DM秘密、事件与已执行操作ID |
| `战斗状态.previous.json` | 上一次已确认的完整进度 |
| `本机身份.json`（历史文件） | 当前版本不再读取或生成，原有文件保留 |
| `团资料.json` / `工作区.json` | 团内战斗列表 / 工作区团列表与最后打开位置 |
| `objects`（战斗状态内） | 每场物件的稳定ID、类型、尺寸、位置、朝向、可见性与阻挡属性 |
| `.battle.lock` | 防止两个进程同时写同一战役；正常停止后自动释放 |
| `损坏存档-时间.json` | 当前文件损坏时保留原件，再从有效备份恢复 |

每个操作先检查团ID、战斗ID、唯一操作ID、期望版本、权限和规则，再串行提交：保存上次完整状态，写入临时文件并同步磁盘，最后替换正式文件。写入失败不提交内存状态、不显示成功；重试前请刷新核对。主文件不可用时从有效备份恢复并在页面提示；必须核对最后一次操作是否需要补做。版本不支持或两份文件均不可用时，停止启动并保留原件。

所有战役文件、资料全文及测试输出均排除出Git。**源码Git保存点不能恢复私人进度。**要保留长期战役备份，请先停止本地服务，将整个战役目录复制到自己的备份位置，再重新启动。需要回到上一次进度时，先备份当前整个目录，在停止服务时用 `战斗状态.previous.json` 的副本替换主文件；不要删除唯一原件。工作区及团索引有各自的previous备份；索引损坏会停止打开并保留文件，需停止服务后人工核对恢复，不会擅自创建空团。每场战斗另保留最近30项操作的撤销快照。界面撤销是一次新的保存，保留原骰点、已执行ID与撤销标记，不会重新掷骰；旧提议会因版本变化被拒绝。撤销不能替代整目录备份。

## 主持交接与扩展

“生成局面包”取得 `local-dm-exchange-v2` JSON，包含明确的 `audience`、局面、版本及操作模板。手动复制给GPT、Workbuddy或人工；是否向外发送私人信息由使用者决定。页面自身没有外部请求。返回 JSON 后粘贴，点击“预览提议”核对，再“确认执行已预览提议”，或者调用同一 `/api/action`。目前只验证人工交换，不承诺现有外部工具的自动控制接口。

操作信封示例（ID与版本必须来自当前局面包）：

```json
{
  "campaignId": "从局面包state.campaignId复制",
  "battleId": "从局面包state.battleId复制",
  "actionId": "每次新操作使用唯一ID-0001",
  "expectedRevision": 0,
  "type": "move",
  "payload": {"actorId": "pc-001", "position": {"x": 27.5, "z": 42.5}}
}
```

| type | payload | 权限 |
| --- | --- | --- |
| `start` | 可选 `modes: {"pc-001":"disadvantage"}` | DM |
| `set-order` | `order: [参与者ID...]`，仅调整同分 | DM，首轮操作前 |
| `move` | `actorId, position:{x,z}` | 当前角色控制者 |
| `dash` | `actorId` | 当前角色控制者 |
| `attack` | `actorId, targetId, attackId, mode` | 当前角色控制者 |
| `next` | `{}` | 当前角色控制者或DM |
| `end` | `{}` | DM |
| `edit-actor` | `actorId, patch, reason`，可选 `publicNote` | DM |
| `edit-board` | `width,depth` | DM，非战斗中 |
| `add-object` / `edit-object` / `remove-object` | 完整物件数据 / `objectId,patch` / `objectId` | DM |
| `add-actor` / `remove-actor` | 新增/复制：`name,kind,ownerId?,copyActorId?`；移出：`actorId` | DM，非战斗中 |
| `set-dice-mode` | `mode: program / physical` | DM |
| `undo` | `{}` | DM |
| `adjudicate` | `actorId, reason`；可选 `damage:[{type,amount}], heal, temporaryHp, resources, consumeAction, publicNote` | DM |

多团API（DM）：`GET /api/catalog`，`POST /api/select {campaignId,battleId}`，`POST /api/campaigns {name,copyCurrent}`，`POST /api/battles {name,templateBattleId?}`。攻击计划 `POST /api/attack-plan` 只返回所需骰型/颗数，不掷骰或暴露敌方数值；攻击可附 `manualRolls:{attack:[原始d20],damage:[[各项伤害骰]]}`。

API：`POST /api/login` 输入 `{id}` 得到会话令牌（DM的id为`DM`，均无需口令），后续使用 `Authorization: Bearer <token>`；`GET /api/state`、`GET /api/handoff`、`POST /api/action`、`POST /api/logout`、DM专用 `POST /api/shutdown`。只接受本机Host及同源浏览器请求，启动器同时核对核心版本与工作区，避免旧核心或另一工作区被误复用；不提供文件系统通配访问。调用本机HTTP接口不需要模型服务。

职责分开在 `src/rules.mjs`（规则和权限投影）、`src/store.mjs`（持久化）、`src/workspace.mjs`（团和战斗索引/切换）、`src/campaign.mjs`（资料载入）、`web/board.mjs`与`web/terrain-view.mjs`（显示）、`web/app.mjs`（交互）。后续主持适配器只交换局面与提议，新增动作沿用同一校验入口；换棋子模型无需改规则占地。存档格式及规则范围都有版本标识；不支持的新版本会拒绝载入，避免静默错算。当前事件写在单一JSON内，长战役时应评估文件体积后再拆日志，首轮未引入数据库。

## 检查

```powershell
npm test
node tests/browser-check.mjs
node tests/flow-check.mjs
node tests/launcher-check.mjs
node tests/desktop-recovery-check.mjs
```

基础测试仅用Node标准库与合成数据。浏览器检查使用现有Codex运行环境的Playwright和已装Edge；可用 `BATTLE_PLAYWRIGHT_MODULE`、`BATTLE_BROWSER` 指定路径，不是运行本产品所需依赖。检查输出集中到 `开发记录/临时/战斗测试/`、`战斗浏览器检查/`、`战斗流程检查/`、`地形检查/`、`多团检查/`、`战斗启动检查/`、`本地窗口恢复检查/`，不使用真实角色进行攻击测试。窗口恢复检查阻断外部请求、通过根目录实际入口启动，在合成战役中保存后强制终止本次测试进程，验证重新打开后可继续修改同一存档。

规则依据为本地固定快照 `c1425c8e90804766689a0db7ec416833f3fc3046` 中《玩家手册2024》“战斗流程”“移动和位置”“攻击检定”“远程攻击”“重击”“抗性和易伤”“临时生命值”。实际执行结果与保存点见工作区 `开发记录/整理记录.md`；资料有翻译与勘误限制，未进行完整官方规则一致性审查。
