# 地图计划 v1

计划为UTF-8 JSON，只保存资料，不包含可执行脚本。字段如下，示例文字需由真实来源替换。

```json
{
  "schemaVersion": 1,
  "module": {"id":"module-id","title":"模组名","version":"来源版本"},
  "source": {"mdSha256":"从索引读取64位摘要"},
  "images": [{"path":"images/map.jpg","sha256":"从索引读取","decision":"map","audience":"dm","evidence":{"method":"direct-visual","note":"实际看到的标题、编号及布局"}}],
  "nodes": [{
    "id":"place-id","parentId":null,"name":"地点名","kind":"image",
    "source":[{"start":10,"end":12}],
    "sensory":{"text":"结合全模组整理的有依据主持提词","sources":[{"start":10,"end":20}]},
    "primaryVariantId":"dm",
    "variants":[{"id":"dm","image":"images/map.jpg","evidence":{"method":"direct-visual","note":"本图与此地点一致的实际依据"}}],
    "hotspots":[{"variantId":"dm","x":0.2,"y":0.3,"targetId":"place-id","label":"区域编号","evidence":{"method":"direct-visual","note":"实际图中位置及对应目标"}}]
  }]
}
```

- `images`必须全覆盖索引的图片，一图一条。decision为`map/illustration/pending`，audience为`dm/player/unknown`。证据method为`direct-visual/context/unknown`。只有实际查看过图片才能写direct-visual，context会保留待核对状态。
- 节点ID稳定且唯一，一个根，无循环；`parentId`仅是目录归属。相同地点的DM/玩家图片放在variants中，不重复建目录条目。不同楼层、插图确为独立平面时可建子节点。文本地图`kind:text`不带图片。
- `source`是基础描述的精确原文行段，1起算、包含首尾；生成器直接摘取，不让AI重写基础描述。不把全章范围当每个房间的依据。
- 移步换景另写`sensory.text`和来源行段，参考全模组人物/剧情。只写有依据的感官，保持“可能遇见/满足条件后发生”，不提前揭示秘密为玩家已知事实。无需硬凑味觉。
- `variants[].crop`可选，格式`{x,y,w,h}`，为原始图片像素整数，裁框不得越界。不要将另一张图的像素或旧缩放图的边框比例直接套过来。公共代码会直接提取原图像素，不修改原件。
- 主显示图为primaryVariantId，省略时取计划首版本。热点variantId省略时属于该主图；坐标相对于**绑定版本裁剪后的图片**，左上为0,0，右下1,1，不能包含HTML标题栏。不能把DM热点自动套在玩家图上。主图待核对而显示备用图时，不匹配的热点不会渲染。
- 不确定的热点用`x:null,y:null`及unknown证据，进入pending；禁止猜测数字。目标必须引用已登记节点。比例尺/指北针是图例；明确地点编号、×、楼层标题、上下行等导航内容应逐一核对。
- 模板中的示例坐标不能直接作为视觉证据。校验通过只表示结构/摘要/引用合法，不验证模型是否诚实查看图片，不等于人工验收。

第一轮不提取完整怪物/物品等资源定义，不生成玩家身份、正式团状态、战斗数据或实际共享授权。第二轮可引用module.id和node.id，原件版本与行号基准继续保持。
