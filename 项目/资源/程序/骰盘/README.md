# 独立掷骰原型

可双击 HTML 使用的离线 3D 骰盘。支持 d4、d6、d8、d10、d12、d20 和成对百分骰，可以混合选择并重复添加同种骰子，一次合计最多 20 颗逻辑骰。支持在骰子和上加一个 1～20 的数值，并保留重播、跳过和刷新恢复。

## 打开骰盘

在文件夹中双击 [命运骰盘.html](命运骰盘.html)，或双击 `启动骰盘.cmd`。启动脚本会直接用默认浏览器打开 HTML。离线文件已生成，不需要 Node、本地服务或网络，也不用保留一个启动窗口。

这个文件约 583 KB，包含界面、样式和同版本 3D 引擎，可以单独复制到其他文件夹。当前已在 Windows 的 Edge 155 断网模式下直接打开并完成检查；其他浏览器未做本轮验证。

旧链接打不开的原因是：`127.0.0.1:4173` 只指向本机开发服务，服务退出后链接就失效。现在日常使用以 HTML 文件为入口。

## 开发与重新生成

修改源码后，在此目录使用 Node.js 20 或更新版本运行：

```powershell
npm run build:offline
```

生成后的 HTML 包含当前源码、锁定版本的三维库和第三方许可。构建脚本使用 Node 内置功能，没有增加打包依赖；不压缩或降低原有模型、材质与渲染配置。

离线 HTML 是可重建的交付产物，排除出 Git，源文件和构建脚本纳入版本管理。切换代码版本后须重新构建，避免继续打开旧的生成文件。新检出目录先执行 `npm ci --ignore-scripts --cache .npm-cache` 安装锁定依赖，再构建；新检出目录不会自带 HTML。

原来的 `index.html` 仍是多文件开发入口，使用 `npm start` 后访问 <http://127.0.0.1:4173>。服务只监听本机；该方式保留给开发调试，退出服务后地址仍会失效。

## 使用方式

1. 点击骰型添加一颗，也可用每种骰型下面的加减按钮或数量输入框调整。各类型同时保留数量，例如选 2 颗 d6 和 1 颗 d20。清空按钮只清空待掷骰池，不删除上一掷记录。
2. 如需加值，勾选“附加数值”，输入 1～20 的整数。不勾选时只计算骰子和。
3. 点击“掷出骰子”，统一投掷并显示每颗点数、骰子和、附加数值和最终合计。例如 `2d6 + 1d20 + 5`，若骰子分别为 1、6、20，最终为 `27 + 5 = 32`。附加数值对整池只加一次。

正式点数和加值先保存到浏览器，再播放动画。重播保留同一组点数与加值，轨迹可以不同；跳过、窗口缩放或动画失败不会重新生成点数，也不会重复加值。更改选择只调整下一掷，点击投掷才生成新的判定。

百分骰的十位与个位外观分开显示；下方结果已经组合为 1 至 100。两颗骰上的 `00` 与 `0` 组合为 100。单独的 d10 中 `0` 表示 10。

保存失败时按钮变为“重试保存这一掷”，沿用待保存的点数。关闭页面前仍须重试成功；尚未写入的内存记录无法跨页面恢复。

每个浏览器、用户配置与地址有自己的本地记录。离线文件和旧网址的记录不会自动互相迁移，离线版也不会删除旧网址中的记录。复制或移动 HTML 可能改变浏览器为文件分配的存储范围，建议把常用文件留在固定位置。

原型只保留最后一次判定，新投掷保存成功后替换它；不是完整历史或战役存档。清理浏览器数据会删除该记录。浏览器若禁止本地文件存储，会明确提示保存失败，不能承诺这种设置下跨次保存。

## 检查

```powershell
npm test
```

17 项自动检查覆盖随机映射、所有 100 种百分骰拆分、混合骰池、附加数值边界、记录兼容、动画结果不一致、本地服务范围和离线构建。离线构建检查要求已有锁定的三维依赖；运行环境若限制回环网络，需要在允许本机连接的环境执行服务检查。

`tests/browser-check.mjs` 另用 Playwright 和已安装的 Edge 检查真实渲染。本轮使用 Codex 已捆绑的测试工具，没有将它添加为运行依赖。复跑时用 `DICE_PLAYWRIGHT_MODULE` 指向已有 Playwright 模块；设置 `DICE_TEST_URL` 为 HTML 的 `file:` 地址即可做断网离线检查，不设置则检查本机开发服务。结果默认输出到工作区的 `开发记录/临时/骰盘/`，也可用 `DICE_TEST_OUTPUT` 指定其他开发输出位置。

此前结果与性能条件见 [测试记录](../../../../开发记录/早期调研/骰盘测试记录.md)。2026-10-25 整理目录后复跑 17 项检查通过，重建 HTML 的 SHA-256 与整理前一致。移动 HTML 后，浏览器按文件地址隔离的上一掷记录可能不跟随迁移；此原型尚无正式文件存档。

## 模块边界

- `src/rolls.mjs`：骰池归并与请求校验、安全随机数、骰子小计、统一附加值、正式记录和显示用骰子拆分。
- `src/journal.mjs`：通过传入的存储接口保存、恢复并校验最后一次判定。当前界面传入浏览器 localStorage。
- `src/animation-contract.mjs`：将正式记录翻译为动画请求，核对动画回传点数；百分骰归组只影响显示层。
- `src/dice-animation.mjs`：唯一接触三维库的适配层，处理播放、中断、尺寸变化和资源释放。
- `src/app.mjs`：界面状态与用户交互。
- `server.mjs`：无额外依赖的本机静态服务。
- `build-offline.mjs`：将同一套源码和锁定库生成单文件交付物；未列入入口图的新导入会明确报错，避免漏打包。

后续换动画库只需保留适配层的初始化、播放与停止接口，并继续通过点数核对。换配色在适配层的主题配置和 `style.css` 中进行。当前附加数值由规则层统一计算，不传给动画库；以后扩展计算规则或优势劣势，也应先更新规则与记录校验。

新记录格式为版本 2，按骰型保存各组点数，并分别保存骰子和、附加数值及最终合计。读取时兼容原来的版本 1，旧数据不改写、不删除；新记录写入独立的 `solo-dice-prototype.last-roll.v2` 键。回退旧代码后仍能读取原 v1 键中的上一掷；旧代码无法展示新版混合骰池。记录不提供防篡改或多人公平性保证。

## 依赖与限制

直接依赖 `@3d-dice/dice-box-threejs` 0.0.12，间接依赖 `three` 0.143.0、`cannon-es` 0.20.0，均由锁定文件固定，包内保留各自 MIT 许可。当前样式使用程序生成的骰面，没有另取外部模型或纹理素材。

旧版库有 d4 缓存、尺寸变化的资源管理和高刷新率下的物理步长问题，已在适配层集中处理，没有修改 `node_modules`。升级时须重跑全骰型与中断检查，并重新审视这些兼容处理。首版尚未加入音效、自定义模型或战斗规则。

保存点与安全回退方法见 [整理记录](../../../../开发记录/整理记录.md)。
