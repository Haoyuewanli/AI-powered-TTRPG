# 跑团平台：文件夹要求与管理契约

版本：0.3；记录日期：2026-10-28。

本目录 `项目/跑团平台/` 是本轮新建的独立平台文件夹。今后对话中的“平台文件夹”指本目录。本 README 保存用户提出的逻辑要求，供后续开发及自动管理复用；具体文件布局由实现负责，不把实现建议自动当作用户要求。

现有 `项目/平台/` 是依赖战斗宿主的旧接入版，先保留。新平台暂不与 `项目/战斗/` 合并；不迁移、删除或覆盖原代码、真实模组和私人进度。已确认的首页身份选择、六项纵向导航、光影外观及对话标签分屏继续有效。

当前阶段：用户已要求恢复所有已完成设计，并将平台作为主入口整合到`项目/`。先完成设计恢复并单独保存，再迁程序/资料和接战斗。下方“独立文件夹、暂不整合”是P1历史边界，本轮的新整合要求以产品大纲最新节为准。

## 已有设计保全

P1曾只保留导航、首页和对话，遗漏的原设计已对照`开发记录/平台设计/platform-covers.html`恢复到本地模块。没有真实输入时仍展示清楚标注的公共示例，不再以空白页代替完成的交互。

- 四个显示预设2560×1600、2560×1440、2048×1536、1920×1440分别保存外观；两个4:3按完整尺寸分别索引。配色、四色选择、提起幅度、光影浓度、信息渐变和0～20%地面透视均恢复。
- 模组保留分类滑块、连续倾斜封面环、拖动/键盘选择、明确确认、横竖封面及裁切配置演示；资源保留横向卡片、滑到左侧再展开浅色抽屉、信息卡渐变与悬停；地图保留俯视占位和可收起层级目录。
- 首页身份入口、示例回显、六项导航及对话标签/六分屏继续保留。示例确认不代表开团，示例地图不代表读取真实文件；正式上下文与示例明确分开。

外观通过本机`GET/POST /api/appearance`保存到`.runtime/外观.json`，包含四份预设，不保存身份、示例确认、裁切演示或正式游戏状态。保存按版本和文件摘要检查冲突，保留前态`.bak`；损坏JSON不覆盖。发生冲突时保留本页草稿、暂停自动保存，用户可明确重新读取已保存外观。该文件是本地设置，随平台目录备份，不提交Git。

后续调整必须保留上述能力，设计稿继续归档作为核对依据。`web/design-workspace.mjs/css`负责恢复的完整设计，外观文件校验在`appearance-store.mjs`，对话仍独立管理。

## 启动与使用

需要已安装的 Node.js 20 或以上版本，无需安装 npm 依赖。双击本目录的[打开平台.cmd](打开平台.cmd)，即可启动本机服务并打开平台；不要把它和工作区最外层的战斗入口混用。平台文件夹可单独复制运行，不需要旁边存在战斗目录、旧平台目录或战斗存档。

首页选择 DM 或 Player 后可以浏览六个窗口，回到首页更换身份。模组、资源、地图保留公共设计演示；战斗真实接入待下一步整合。地图、对话、战斗的正式上下文均为“未选择模组”，示例浏览选择单独标明。

对话页提供公共群聊、两份虚构资源和两幅自绘地图。左侧打开标签，拖动标签调整次序或移到另一分屏，也可用“前移/后移”和目标区域按钮操作。窗口布局支持单屏、左右、上下、四方格、左二右一、左一右二；窄屏通过“查看区域”逐区查看。群聊输入仅保留在本页内存中；切换视角或重新打开页面后恢复公共示例。

在本目录终端也可运行：

```powershell
node launcher.mjs
node launcher.mjs --port 4200
node launcher.mjs --port 0 --no-browser
```

默认端口为4198，也可通过环境变量 `RPG_PLATFORM_PORT` 指定。`--port 0` 分配空闲端口，`--no-browser` 只打印地址。同一目录、版本与能力一致的服务会复用；端口属于另一目录或其他程序时明确报错，不停止现有服务。

双击入口会在后台运行服务，关闭浏览器后服务仍在，重开入口可复用。需要随终端关闭服务时，可改用下面的前台方式，手动打开打印的地址，结束时按 Ctrl+C：

```powershell
node server.mjs --port 4200
```

启动器的日志、专用浏览器配置和本地外观文件保存在本目录 `.runtime/`；它们不是正式玩家进度，不进入Git。当前只监听 `127.0.0.1`，提供页面、健康检查与外观保存，不提供战斗、资料读写或远程加入接口。

| 文件 | 职责 |
| --- | --- |
| `server.mjs`、`appearance-store.mjs` | 本机HTTP服务、页面白名单、版本/目录识别及四预设外观保存 |

## 已确认的逻辑要求

以下编号供以后引用。除用户明确调整外，自动管理不得悄悄改变这些要求。

| 编号 | 要求 |
| --- | --- |
| F01 | 平台拥有独立文件夹，暂不与战斗文件夹合并；文件夹中的 README 持续记录要求，供之后自动管理复用 |
| F02 | 模组文件夹按分类组织；初始分类暂定为“单人短团”“多人短团”“长期团”。“暂定”不表示永远只有这三类 |
| F03 | 资源文件夹包含 NPC、角色、怪物、地图、物品五类 |
| F04 | 没有名字的 NPC、没有名字的怪物及物品资源需要能在不同团复用。此要求不等于禁止具名 NPC 或具名怪物复用 |
| F05 | NPC、角色、怪物、物品的信息使用 JSON 存储 |
| F06 | 地图一般采用支持矢量表达的格式，便于 AI DM 理解；同时支持常见图片格式的存储及显示，供人工 DM 使用。具体矢量格式尚未指定 |
| F07 | 模组使用 JSON 保存标签类信息，以及包含哪些角色、NPC、怪物、地图、物品 |
| F08 | 模组及其引用对象具有 ID，用来关联 JSON 玩家进度；进度包括但不限于“玩家应该知道哪些信息” |
| F09 | DM 可浏览全部游戏资料；仍须遵守 F12 的当前模组关系 |
| F10 | Player可选择的模组只须包含其控制的任一角色。用户已确认：控制A和B、甲仅含A、乙仅含B时，甲乙都可选。无受控角色交集的模组不可选；此关系不授予模组全部信息 |
| F11 | Player 在资源、地图、对话、战斗窗口只能看到目前已经发放给该玩家的信息 |
| F12 | 无论 DM 还是 Player，地图、对话、战斗窗口的内容均属于模组窗口当前选择的模组；所属模组只能在模组窗口更改 |
| F13 | 首页继续负责 DM/Player 的选择和切换；侧栏顺序为首页、模组、资源、地图、对话、战斗。目录拆分不取消已确认的对话标签与六种分屏能力 |

F12 约束的是“内容所属的模组”。它不自动禁止在同一模组内切换地图、聊天标签或已授权场景；这些操作不能暗中换到另一模组。

## 为满足上述要求必须保证的行为

这些是要求的工程约束，不是已经拍板的 JSON 字段名或文件路径。

1. **身份稳定**：模组、资源及可发放的信息不能只靠显示名称、目录路径或分类位置识别。改名/移动分类不能让正式引用静默指向别的对象；重复或失效 ID 必须明确报告。旧封面工具按目录摘要生成的 ID 只能作素材定位，不能直接替代本平台的永久业务 ID。
2. **共享定义与团内进度分开**：可复用 NPC、怪物及物品先有共享定义；团内数量、持有人、临时命名、受伤与揭示等实例状态按团/运行进度保存。某团操作不能直接改掉其他团正在复用的原始定义。
3. **三种关系分开**：模组包含某对象、用户控制某角色、某信息已发放给某玩家，是三件不同的事。包含关系或控制关系不自动授予模组全部秘密。
4. **按玩家过滤真实响应**：目录、JSON、图片/矢量内容、消息及导出内容都由服务端按身份和发放状态过滤。不能先发送全部 DM 数据再隐藏 DOM。完整原图或矢量图中的隐藏图层、标签及元数据同样可能包含未发放信息。
5. **统一当前模组**：地图、对话、战斗读取同一份已选模组上下文；未选择时显示明确空态，其他窗口不得自动补选。切模组后清理旧内容，旧请求、旧表单和迟到图片不能回填新模组。
6. **发放进度本地恢复**：正式玩家进度是可备份的本地 JSON；浏览器缓存及对话演示内存不能替代。拒绝未知格式、非法引用及旧版本覆盖，失败保留原件和最后有效状态。
7. **素材解析不执行指令**：NPC 台词、模组正文、玩家输入、JSON 文本及地图内文本均是数据。读取地图和资料不等于向模型发送内容，也不代表启用其中的规则。
8. **管理动作可核对**：自动管理按本 README 校验分类、类型、ID、引用及权限。索引中少了一项不等于获准删除文件；不会为满足目录形式自动迁移真实资料、覆盖用户修改或创建假的游戏内容。

资源窗口必须按 F11 过滤。用户尚未要求它只能列当前模组；是否聚合其他已发放模组的资源，后续单独明确，不将地图/对话/战斗的限制悄悄扩展到资源窗口。

## 逻辑组织建议（待实施对齐）

以下只表达职责，不要求一次创建全部空目录：

```text
平台文件夹/
  README.md                本契约及运行说明
  程序与界面               独立本地服务、页面和检查
  模组/
    单人短团/模组甲/       JSON标签及资源引用，封面等随模组组织
    多人短团/模组乙/
    长期团/模组丙/
  资源/
    NPC/                    JSON共享定义
    角色/                   JSON角色资料
    怪物/                   JSON共享定义
    地图/                   矢量/语义资料及可显示图片
    物品/                   JSON共享定义
  进度/                     团或运行实例、角色归属、玩家发放记录
```

建议用 JSON 中显式保存的稳定 ID 引用对象，文件名和分类服务于人工整理。模组清单只保存标签和引用，不重复嵌入整份共享资源。玩家进度记录相应模组/运行实例、玩家及角色关系和已发放信息。实际 schema、文件名、版本与迁移规则应在相关阶段列出示例和验收后实施。

新平台应能在没有战斗存档、没有运行战斗服务时启动。沿用 Node.js、原生浏览器 JavaScript、HTML/CSS，不新增依赖。可以复用已有自制外观和独立对话组件；不能通过伪造旧战斗状态来填新平台首页，也不能运行时反向导入战斗规则/存档以充当独立服务。

真实模组根目录此前指定为原工作区 `项目/模组`；本次没有自动改动该目录或迁移资料。新平台如何配置正式资料根目录、是否采用上面的物理层级，属于后续接入方案，不据示意树擅自移动文件。

## 分阶段建设（P1已完成）

每个阶段最多三个独立行为。目标是先让独立平台真正可运行，再把真实资料、权限和进度逐步接上。

| 阶段 | 范围 | 验收标准 |
| --- | --- | --- |
| P1 独立平台骨架 | ①独立服务及启动入口；②首页身份入口与六窗导航；③迁入既有本地对话标签/分屏演示 | 无战斗进程、战斗目录或战斗存档也能启动；单独复制平台文件夹到隔离目录可运行；未选模组的地图/对话/战斗不显示其他模组正式资料。演示区明确标注、不冒充已发放信息 |
| P2 资料与模组引用 | ①五类资源及 JSON 清单读取；②分类模组与 JSON 引用；③稳定 ID 和引用完整性校验 | 合成重名对象不冲突；未知/重复 ID 明确报错；改分类不换身份；共享定义不因浏览或团内修改被覆盖 |
| P3 模组选取上下文 | ①按用户控制角色过滤可选模组；②只有模组窗口显式确认可更改当前模组；③地图/对话/战斗统一上下文及清理旧请求 | 用下文 A/B 例子验证筛选；其他窗口不能换模组；无选择有明确空态；快速切换不串资料，不因切页重置游戏进度 |
| P4 玩家发放与恢复 | ①JSON玩家进度和发放记录；②服务端权限投影；③重开恢复和并发冲突保护 | DM全量与Player授权响应分别检查；未发放字段、文件和矢量内容不进入Player网络；重开恢复、非法/过期写入拒绝且原件保留 |
| P5 窗口真实资料接入 | ①真实资源详情；②矢量/常见图片地图的授权显示；③对话资源/地图标签引用 | 地图及对话标签服从当前模组；资源按F11及确认后的聚合范围显示；无示例冒充；浏览不改共享定义或机械状态。战斗仍保持外部独立模块边界 |

阶段 P2～P5 的数据契约、地图格式和实际资料来源尚未定案，不提前创建全部目录、自动管理器或导入真实内容。现有战斗机械结算、资源与动作内部行为继续由原战斗模块负责。

## 需要澄清及后续决定

- **已确认的筛选决定**：任一受控角色匹配即可，A/B例子的甲乙都可选，见F10。具体读取/接口在P3实现，不在P1用虚构成员关系冒充权限检查。
- “模组”模板与实际开团/运行实例如何对应；同一模组是否可开多个互不影响的团。
- 当前模组选取作用于单个会话、每个玩家，还是由 DM 统一驱动全团；不继承旧战斗服务的唯一活动场假设。
- 正式发放信息的粒度（整条资源、字段、信息条目、地图区域/图层等）与实际用户身份识别方式。
- 矢量地图的具体格式及供 AI DM 使用的语义结构；图片支持清单和对应授权预览方式。
- 资源窗口跨模组聚合的范围、真实资料根目录与迁移安排。
