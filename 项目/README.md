# 战局：本地跑团平台

双击本目录的`打开平台.cmd`，或工作区根的`打开跑团.cmd`。沿用已有Node.js，不安装依赖。当前程序版本为`platform-workspace-v13`。

开卡与升级使用独立入口：工作区根的`打开开卡升级.cmd`，或[本地开卡工具](程序/开卡升级/README.md)。支持分轮引导和自由填写、1至20级单职业开卡及后续升级；玩家并排阅读多个TXT，只填写`回答.txt`。说明书、Agent提示词和预制逐级TXT库位于工具目录，既有角色目录保持原样。

## 文件放在哪里

```text
项目/
  模组/<可选分类>/<模组>/
    模组.json、封面.jpg
    资源/<分类>/<条目>.md、示例模版.md
    地图/地图包.json、地图.html、图片/
    游玩团/<团ID>/团.json、画布.json、群聊.json
    游玩团/<团ID>/战斗桌/工作区.json、本团战斗/战斗状态.json
    画布.json                 模组准备画布，与团内画布分开
  预处理/
    0. 待处理模组/<可选分类>/<模组>/     人类准备的MD、图片、PDF
    1. 处理地图/Code/、输出/
    2. 处理资源/Code/、输出/
    玩家/Code/、模版/、<玩家>/<角色名-模组>/<01级>/
  资源/<世界资料分类>/       固定MD、示例模版.md
  资源/玩家/<玩家>/<角色名-模组>/<01级>/选择.md、能力.md
  程序/
    平台/Code/               服务、外壳及检查
    平台/窗口/<窗口>/Code/   模组、资源、对话、地图、玩家和战斗接线
    战斗/Code/、骰盘/Code/、封面工具/Code/
```

模组原始输入和各轮处理只在预处理目录进行，核对后复制成果到正式模组。资源窗口的“模组”卡展示各模组自己的资源；除单独私有的玩家档案外，世界资源目录存怪物图鉴、规则、法术、职业、种族、背景、专长、物品、人物、世界观、世界地图。原5E JSON保留为机械读取兼容文件，界面条目以MD为正文来源。`资源/资料/`保留原始不全书，程序已移出资源目录。

旧模组、旧团及关联资源已按2026-11-02授权从活动目录归档，备份与摘要在工作区`开发记录/临时/目录调整-20261102/备份/`。不会因打开旧团名自动替换引用；不要把备份直接覆盖到新目录。

## 从正常入口操作

选择DM后，从首页“选择模组”或侧栏模组进入。分类紧接标题；封面环支持左右键、按钮、拖动和滚轮。点击封面或确认后，小封面移到左侧，背景副本模糊；新建团、修改封面在下方，已有团在右侧常显时间、角色与玩家。点“继续此团”才切换当前团。重命名和建立副本在条目右侧；删除团会移入该模组“已归档团”，保留完整文件并使旧邀请失效。副本复制团、画布和群聊，不复制开放授权或邀请。

文件管理器中可创建任意分类层级、移动整本模组或添加新模组，然后点击“刷新目录”。模组由有效的`模组.json`识别，其中`id`必须唯一且保持稳定、`name`为显示名称。直放根目录的模组显示为“未分类”。空分类会列出；坏文件、缺文件及重复ID单独提示，其他模组继续可用。移动后的团和地图继续按原ID查找；移出当前模组后清除失效选择，有未保存草稿时保留标签等待恢复目录。刷新不迁移或重写资料。

模组页底部到环状切换与确认按钮为止，外观设置和其他尾部内容不在该页显示；目录问题显示在工具条下方。

资源页的分类带小图标，有A～Z与模组多选筛选，均只影响浏览。世界资料默认开放；模组正文仅DM可见，只有地图、人物和怪物的图片可以按当前团角色开放，玩家收到图片而不收到主持正文。同一资源视图只展开一个条目，右侧显示安全渲染的MD和本地图片。风骸岛已核对的18幅人物/怪物配图与17种地图版本通过只读图片索引接入，不改原MD及图片。

玩家是DM侧栏的同级主区页面，默认打开“关系总览”。按玩家排列角色，可搜索玩家、角色、模组或团，也可勾选“只看未入团”。单击角色即可查看所属玩家和参加的团；所属玩家下拉保存后，正式目录随之移动，角色身份和参团关系保留。角色详情可以直接阅读最新已记录等级的能力，也可进入等级文件夹。

“选择参加的团”是按模组分组的多选下拉。保存前显示加入、移出和关联说明，可放弃草稿；同一角色可加入多个团，共用档案，各团画布、聊天和进度独立。已有团内角色显示为“未关联档案”，可明确选择“关联已有：角色名”，不按名字自动合并。操作不切换当前正在游玩的团，也不复制或改写档案正文。已参加团可直接生成、复制或撤销本机邀请，无须切到对话页。邀请仍限定现有本机服务，不代表跨设备联机已完成。

玩家资料仅DM和获准所属玩家可读。新关联的团成员自动使用该档案所属玩家的身份；旧绑定入口折叠为“已有邀请兼容设置”，仅兼容过去的邀请授权，不表示角色归属或参团。角色换玩家后，旧身份失去该角色访问能力；新玩家不继承旧玩家的模组图片授权。成员发生变化的邀请需要重新生成；未变化团和其他玩家的邀请保持。移出、再加入会建立新的团内成员身份，旧分享不会复活。

“档案文件”保留原文件管理：双击进入玩家、角色和等级，右键操作；支持新建、重命名、剪切/复制/粘贴、副本、拖动移动和Ctrl拖动复制。当前目录可搜索，无选择或不适用的操作禁用。新建等级生成固定选择/能力MD；可阅读、编辑、保存。保存冲突和未保存的归属、参团、绑定、MD修改会提示先处理。正式操作只修改`资源/玩家`；预处理副本保留。

参团关联作为可选字段保存在原有`模组/资料库工作区.json`中，以稳定档案ID及模组/团ID关联；团.json原始名单保留，运行时合成成员，不把合成结果再次写成新名单。显式关联旧成员后移出，会保留解除关联标记，避免旧角色与授权自动复活。模组移出时关联显示暂不可用；要修改其他关联，可先恢复目录，或明确取消失效关联。手工复制索引导致重复ID的档案暂不可关联，需核对身份。复制档案不带参团关系，复制团生成新的参团身份且不继承邀请和分享。新增关联需求集中扩展player-relations服务，文件编辑和资源渲染继续复用原实现。

资源条目使用渐变底色，点击立即显示展开/读取状态，只接受最后一次展开的结果；界面已移除引用入口，模组图片统一通过本团角色多选下拉授权。

对话页采用浏览器式标签，加号新建标签后有搜索与“群聊、共享通知、资源、地图”入口。资源标签与资源窗口调用同一个组件，可多开，每页筛选和展开状态独立。拖标签到边缘会预览左右或上下分屏，拖到角落可上下左右四分屏；侧边栏也可直接切换布局。关闭有草稿的聊天或地图标签前须先保存或清空。群聊保存到当前团，可用“刷新群聊”读取更新。角色与玩家邀请在标签页左侧菜单中。

“共享通知”记录本团开放与撤回。Player用角色绑定的专属邀请进入，只看到给自己受控角色的提示；点击分享定位并展开资源。撤回后后端拒读，打开的资源标签及正文会清理。世界资料的默认开放不等于机械规则启用。当前服务仍限定本机；本机邀请不代表已完成第二设备或公网联机。

地图页复用第一轮完整HTML工作台。多选模组后选择当前画布，仅切换浏览地图；当前团所属模组保存为团内画布，其他模组或无团时保存为“模组准备画布”。保存写本地文件；重置恢复默认布置，可撤销；Ctrl+Z及撤销按钮撤回，Ctrl+Y及恢复按钮重做。切换画布保留各自草稿，重新挂载工作台会重新建立当前画布的撤销历史。冲突不覆盖文件，可明确重新读取放弃草稿。地图包换版不自动套用旧布局。

地图页去掉外层冗余标题，画布及工具沿用原完整工作台。地图图片可从资源窗口按角色开放；地图编辑器内的共享按钮仍为占位，地图目录、主持提词和编辑对象不开放给玩家。Player的地图标签只展示获准图片。

## 战斗页与创造搭建

战斗页去掉外层大标题，以原战斗核心为主体。先在模组页继续一个团，再进入战斗页：“打开本团战斗”只读取已建立的战斗，“建立本团战斗”明确创建该团下独立战斗桌。新场景为空，全部参战者从参战者栏“＋”加入，复制选中棋子也在此入口。既有独立战斗入口和存档继续保留，不自动搬入新团。

“＋”可新建角色、NPC、怪物或搜索平台人物/角色/怪物资源。明确结构化数值及固定能力MD表格可预填，找不到的值清楚标为待填占位。加入的是本场草稿，来源正文保留、资料未确认，须DM核对后开战。原角色档案不回写本场受伤和消耗。模型尺寸与规则占地分开设置，怪物使用统一可调长宽高的方块模板。新资料库玩家邀请与战斗控制ID仍是两套现有入口，战斗玩家使用其战斗邀请；没有将两个邀请体系按名字自动合并。

DM点击画布内“创造搭建”，用WASD移动、Space上升、Shift下降，拖动环视或点击“鼠标环视”锁定鼠标，Esc退出。基础单元为1×1×1尺、5×5×5尺；也可选当前积木。默认右键放置、左键破坏，工具栏有同名按钮。准星透明预览不写进度，确认的放置/破坏沿用版本检查、持久保存与撤销。DM开战中仍可搭建，Player没有这些入口。旧地板、坡块、半尺与大型几何保持兼容，不迁移原地形。

外观目录覆盖当前本地40种独立种族×13基础职业，共520个稳定组合（2024默认10×12=120），排除明确子种族汇总和说明页；外观选择不授予职业能力。15种武器家族有持握几何与动作，当前攻击可临时展示对应武器；魔法共用粒子形状，只变颜色。已保存的可见攻击事件驱动DM与Player动效，未授权隐藏目标不下发动效，重开不重播历史。

后续模型从公共外观目录和几何组件扩展，建造交互与机械结算分开。复杂法术、角色规则合法性及NPC行动选择仍按原战斗设计处理，视觉表现不等于全部能力自动化。

## 当前风骸岛成果

第二轮195条非地图资源、29张本地配图；第一轮34地点、17图片版本、69热点，均已复制至正式模组。来源行号、版本、候选状态保留。原书旧版规则不自动启用；所有资料收录与机械能力实现分开。

5010条世界资料已派生为MD，保留原JSON及其摘要；11种目录均有示例模版。内容未重新逐条进行语义审核，仍为candidate。MD前置JSON只放身份、版本、来源及结构化补充，正文在其后；团内授权、邀请及画布另存，不把共享资源复制到每个团。

## 开发与检查

在`程序/平台`运行`npm test`，在`程序/战斗`运行`npm test`。直接命令为`node 程序/平台/Code/launcher.mjs --no-browser`。新版浏览器验收为`node 程序/平台/Code/tests/promoted-ui-browser-check.mjs`及`node 程序/平台/Code/tests/new-library-integration-browser-check.mjs`、`node 程序/平台/Code/tests/player-ui-browser-check.mjs`及`node 程序/平台/Code/tests/player-relations-browser-check.mjs`，均使用独立合成资料。地图和资源预处理分别见对应README，通用代码与合成检查在各自Code内。

本地文件是正式状态，机械结算仍由原战斗核心处理。独立战斗入口保留，新资料库团须明确建立空白战斗，不自动生成为训练战斗；旧甲板专用团已按授权归档，不用旧团快照冒充新资源定义。

输入原件、第三方全文、派生资料、私人团、邀请、缓存和备份不提交Git；通用代码、规范、模板与合成检查提交。实际检查和未完成的内容审核见工作区产品大纲与整理记录。
