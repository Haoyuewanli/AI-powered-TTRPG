# 战局：D&D 2024 跑团平台

现在“平台文件夹”指整个 `项目/`。平台是主要界面；程序代码在 `程序/`，游戏文件在模组、资源、当前、战斗、对话五个数据目录。已完成的设计、动效和公共示例继续保留，不因真实资料尚未接入而删掉。

## 打开与开发

双击本目录的 [打开平台.cmd](打开平台.cmd)，或工作区最外层的 `打开跑团.cmd`。需要已有Node.js 20或以上版本，无需安装新依赖。默认优先本机端口4198；若被旧平台或其他程序占用，会自动选择空闲端口，保留原服务。实际地址记在程序目录`.runtime/launch-*.json`，重开先核对程序目录、资料根、版本及能力，再复用正确服务；失效记录会重新探测。关闭浏览器后后台平台服务仍在。

命令行 `node 程序/平台/launcher.mjs --port 0 --no-browser` 可新选空闲端口并打印地址。显式`--port`或环境变量`RPG_PLATFORM_PORT`属于固定端口要求：冲突时仍报错，不自动换端口或连接别的项目。

需要随终端结束服务时，用 `node 程序/平台/server.mjs --port 4198` 前台运行，结束按Ctrl+C。可用 `RPG_PROJECT_ROOT` 指定另一份项目资料根；测试必须指向合成目录，不使用真实进度。

首页选择DM/Player，侧栏顺序为首页、模组、资源、地图、对话、战斗。本机DM可展开各页的本地文件区。模组页可选择带稳定ID的真实模组，或“载入已有战斗团”后选择兼容团和战斗；只有模组页改变所属模组。战斗在独立本机服务及隔离窗口中运行，仍需在其中明确选择身份。平台不会自动代登录、开战或消耗资源。

Player入口当前保留公共设计预览，真实文件接口拒绝访问；记录“发放给某玩家”不代表已经完成正式玩家登录和跨设备发放。真实Player接入沿用战斗的邀请/身份能力逐步衔接，不新增账号服务。

## 已确认的目录与逻辑要求

| 编号 | 要求及当前落点 |
| --- | --- |
| F01 | 平台是主入口。`程序/平台`和`程序/战斗`分别维护，战斗内部规则、动作、资源行为保持独立，不复制到其他窗口 |
| F02 | `模组/分类/模组/`保存模组PDF、封面和调用JSON；初始分类为单人短团、多人短团、长期团，分类可扩展 |
| F03 | `资源/`是所有资源和存档的长期存储，一级为角色、NPC、怪物、地图、故事；二级为A～Z。英文按首字母，中文按拼音首字母 |
| F04 | NPC、角色、怪物和物品信息使用JSON；无名NPC、无名怪物和物品须能跨团复用。复用不让某团修改自动覆盖共享定义 |
| F05 | 地图支持矢量表达及常见图片；当前资源浏览可展示SVG、PNG、JPEG、WebP、GIF。AI语义地图和完整地图业务仍待接入，不向模型发送本地内容 |
| F06 | 模组调用JSON保存标签、角色/NPC/怪物/地图/物品引用；对象必须有稳定ID，改名或移动分类不能静默换身份 |
| F07 | `当前/模组名/`保存共享定义的基准引用、团内实例和变化量。生命、法术位等可恢复资源通常为相对满额基准的负数；非数值状态明确标为绝对覆盖，不猜测规则 |
| F08 | `战斗/模组名/战斗ID/`保存战斗调用JSON和TXT日志，调用资源及当前实例；不在该目录混放战斗程序源码 |
| F09 | `对话/群聊名/`保存时间戳及消息内容的Markdown和群聊调用JSON。资源引用使用相对于整个项目目录的路径，元数据写 `referenceBase: "project"` |
| F10 | Player可选模组包含其控制的任一角色即可；控制A/B、甲仅含A、乙仅含B时，甲乙都可选。此筛选已确认，正式玩家资料关系尚未接入 |
| F11 | DM浏览全部资料；Player仅获得已发放信息。包含关系、角色控制关系、信息发放关系分别维护，不能靠前端隐藏秘密 |
| F12 | 地图、对话、战斗内容属于模组页当前选择的模组；其他窗口不更改所属模组。示例内容明确区分，不冒充当前模组正式资料 |
| F13 | 资源右键及“更多”提供引用、开放给某玩家并引用、打开文件夹位置。引用与发放写入本地文件，发放范围当前为整条资源 |
| F14 | 首页负责DM/Player选择和切换；离开战斗须等待保存、处理角色/地形草稿。换身份及重开清除旧视角和票据，迟到响应不能回填 |
| F15 | 已有完整UI、动效和示例不丢失；四显示预设2560×1600、2560×1440、2048×1536、1920×1440分别保存外观，两个4:3仍独立 |

中文归档使用本机拼音排序推导；多音字和特殊字符标记待核对，写入接口允许显式指定首字母。既有战斗没有区分NPC/怪物的记录保持NPC分类，不凭名字猜类型。最新目录未将物品列为独立一级目录：现有战斗物品目录和库存能力完整保留，独立共享物品文件的分类接法留给后续开发，不自动搬成故事或删除。

## 文件格式与实际组织

```text
项目/
  打开平台.cmd
  README.md
  程序/
    平台/                  主界面、本地文件管理、战斗外置适配
    战斗/                  最新独立战斗程序、Three.js接线及原测试
    封面工具/              原图不变的真实封面管理
  模组/
    单人短团/模组名/       PDF、模组封面.png或.jpg、模组调用.json
    多人短团/
    长期团/
  资源/
    角色/A...Z/            JSON定义及相关文件
    NPC/A...Z/
    怪物/A...Z/
    地图/A...Z/            矢量/语义JSON及图片
    故事/A...Z/
      F/发放记录.json
      G/管理索引.json        稳定ID、事务与路径登记
      Z/战役存档/           兼容战斗权威快照和原内部相对树
  当前/模组名/当前.json
  战斗/模组名/战斗ID/
    战斗调用.json
    战斗日志.txt
  对话/群聊名/
    群聊.json
    对话.md
```

初次显式打开本地文件区会初始化数据目录与A～Z。模组清单当前识别 `模组调用.json` 或 `module.json`，至少包含 `{ "id": "module-1", "name": "模组名" }`；其余标签/资源引用原样存文件，完整校验和开团导入未自动实现。资源JSON须显式带 `id`；非JSON由管理索引分配ID，原路径更新保持ID，移动后按摘要重定位，重复或不明确的身份会报告问题。

当前文件的实例包含 `id / resourceId / base / delta`；同一NPC在不同战斗有不同实例。重名或非法目录名会使用稳定ID后缀，显示名仍保留。群聊的Markdown链接示例为 `(<资源/NPC/A/阿德.json>)`，明确按项目根解析，不能按Markdown文件所在目录误读。

文件管理有串行队列、版本校验、目录链接/硬链接拒绝、跨文件事务意图及恢复保护。坏JSON、外部修改、过期写入不静默覆盖；异常现场保留。索引和内部兼容存档不被当普通公开资源。资源读取及单次投影有16MB边界，超限明确报错。

## 设计、资源与对话操作

完整归档设计继续作为核对依据。四尺寸、四配色、基础颜色、浮起幅度、大块光影浓度、信息卡渐变及0～20%地面透视都可调；外观保存在 `程序/平台/.runtime/外观.json`，有版本/摘要冲突保护及前态备份，不混入游戏进度。

模组仍有分类滑块、连续倾斜封面环、明确确认及横竖裁切演示；资源仍有横向卡片、先滑左再开浅抽屉和渐变信息卡；地图仍有中央俯视占位和可收起层级目录。真实文件区是单独展开的薄片，保留这些设计示例。真实封面管理从模组页的本地文件区进入，沿用原图保护及中央 `cover-crops.json`，不是用演示裁切冒充真实保存。

对话保留公共示例群聊、资源/地图标签和六种分屏。DM在资源列表点击真实资料，可在同一个标签分屏系统打开；右键引用后，在当前模组的真实群聊中发送，保存消息及项目相对引用。真实群聊与示例输入分开；示例仅本页内存，真实群聊可从本地Markdown恢复。尚未接跨设备实时聊天或AI。

## 战斗兼容与迁移

战斗采用原分支最新 `class-resource-tests-v8`，规则、操作、资源和内置数据保持原样。兼容权威快照存于 `资源/故事/Z/战役存档`；外置投影按版本生成共享基准、当前增量、调用文件与TXT日志，通常每两秒检查一次。共享基准首次建立后不被投影覆盖，同版本不重复写；同步失败会在战斗外层显示，原快照仍是权威数据。

当前JSON是可重建的兼容增量视图；不能直接编辑它来绕过战斗事务或代替权威快照。游戏内日历未定，本轮不把电脑日期当作冒险日，也不改变长短休结算。将来若要让增量成为战斗权威输入，须由战斗开发对话明确迁移并回归，不能同时保留两个可写真相。

旧 `存档/` 先备份再复制，源目录保留。迁移工具：

```powershell
node 程序/平台/migrate-storage.mjs --project-root .
node 程序/平台/migrate-storage.mjs --project-root . --apply
```

第一条只核对计数；第二条检查活锁、备份到工作区 `开发记录/临时/迁移备份/`，再独占复制并逐文件验证摘要。已有不同内容、链接逃逸或活进程锁均拒绝，不停止其他服务。备份及源文件都不提交Git。旧目录和新目录不能同时启动为两套正式进度；迁后日常入口以新资源根为准。顶层统一入口会把旧显式campaign/workspace路径映射到已迁目标，缺目标时拒绝回落到旧副本。已为注册的3场旧战斗离线建立资源基准、当前增量及调用/日志，未改变权威快照。

战斗可独立使用 `程序/战斗/启动战斗.cmd`，或 `node 程序/战斗/server.mjs --workspace <兼容存档根> --campaign <团目录>`。内嵌只允许确切父origin，跨窗桥只传生命周期确认；旧战斗页的团/战斗切换接口在内嵌模式被拒绝，平台模组页使用独立适配器调用。原机械结算、邀请及主持接口不复制到平台。

## 验证与后续边界

平台检查在 `程序/平台/` 内运行 `npm test`；浏览器脚本在其 `tests/` 中，包括原对话、设计保全、文件菜单、平台战斗内嵌。战斗检查在 `程序/战斗/` 内运行 `npm test`。独立工作树没有被忽略的PHB全文时，可用测试专用 `RPG_REFERENCE_ROOT` 指向已有原工作区；不下载新全文或削弱存在性断言。临时截图、合成数据与检查日志均在工作区 `开发记录/临时/`。

本轮完成和实际检查数、保存点、真实迁移结果与战斗交接单见 [整理记录](../开发记录/整理记录.md)最新节；未决事项统一见 [产品大纲](../开发记录/产品大纲.md)。后续仍包括正式Player邀请与受控角色筛选、字段/地图区域发放、模组开团、完整真实地图窗口及跨设备聊天。现战斗核心仍是单活动团/战斗；多个DM页面并发切所属模组的协调需后续完善，不据单窗口验收宣称多房间支持。

私人资源、进度、聊天、调用文件、备份、缓存与密钥不进入Git。不联网发送游戏数据，不自动调用模型、安装依赖、推送或发布。独立骰盘与原本地规则资料继续保留，入口见原有相应目录。
